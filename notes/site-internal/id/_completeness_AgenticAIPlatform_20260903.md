# Completeness Critic — Agentic AI 平台 ID（2026-09-03）

## ① 獨立一階變數清單（讀草稿前列出）

1. **競爭替代（intra-layer 份額消長）**——同棧層內誰搶誰的單，決定收入是否可持續，不只是「有沒有 agent」。
2. **地緣供給（GPU／資料中心／出口管制）**——agent 的運算產能來自模型商資本支出，資本支出受晶片出口管制與地緣政治直接約束，是上游硬約束。
3. **需求方自供（build vs buy／超大型企業自建）**——最大買家（銀行、政府、超大型科技公司）若繞開所有上市標的自建，直接封頂可觸達市場。
4. **監管（跨轄區、非僅 EU）**——agent 自主操作觸及責任歸屬、資料主權、金融/醫療業特定合規，決定哪些工作流「被允許」自動化，直接決定誰先收得到錢。
5. **相鄰棧顛覆（模型商/雲端上攻應用層）**——若模型商直接吃掉應用層，目前的價值鏈分配全部作廢。
6. **計價與毛利機制**——本主題核心變數，決定誰的收入基礎在流失、誰在補位。
7. **分發與結帳權（協議層／agentic commerce）**——誰控制入口與付款，誰就能對其他人抽稅，是五年後利潤池歸屬的關鍵。
8. **勞動替代驗證（實證，非敘事）**——「agent 真的取代了多少人力」需要可查證的獨立數據（裁員統計、生產力研究），否則整條需求論證只是敘事外推。
9. **開源與中國替代**——免費/低成本開源編排層＋中國低價模型若把模型與編排層價格壓到接近零，會重塑全球定價曲線與應用層毛利假設。
10. **安全事件／資安風險**——agent 自主操作＋高權限＝新攻擊面；一次重大資安事故足以改變採用速度與監管態度，尤其當論點的護城河正是「權限與稽核」。
11. **客戶集中度／大客戶流失風險**——早期新品類收入常集中在少數指標客戶，流失一家即動搖整個成長曲線判讀。
12. **保險/責任分攤市場成熟度**——agent 出錯的財務責任由誰承擔（保險、合約條款），是採用摩擦的下游指標（優先度較低，第三順位變數）。

## ② 缺席變數（草稿完全沒提到，或僅以排除聲明處理）

### D1. 監管深度（跨轄區、agent 法律責任歸屬）
- **為何一階**：驗收能力與監管許可權直接決定「哪一層先收得到錢」（草稿自己在 §3.3 承認「造王者是稽核與合規要求，不是技術長」），但監管本身只出現一次（EU AI Act 高風險義務生效日，作為單一催化劑項）。
- **草稿處理狀況**：無明文排除聲明；「刻意不做的三件事」清單未提及監管範圍限縮。等於是一階變數被降級成單一日期型催化劑，深度不足以支撐其自稱的重要性。
- **建議補到**：mechanics（§3.3／§3.4，作為換相條件之一）或 risks（§5 否證表新增一條，如「美國聯邦/州級 agent 責任立法進度」）。
- **建議查什麼**：美國各州 AI 責任法案進度（如 Colorado AI Act）、金融業（SEC/FINRA）與醫療業對自主 agent 決策的既有規範、企業合約中 agent 錯誤的責任條款慣例。

### D2. 開源與中國替代（全球低成本模型/agent 平台）
- **為何一階**：草稿本身已承認「開源編排框架把價格壓到接近零」是供給側最重要事實之一，但只談美系開源框架，完全未提中國模型商（DeepSeek／阿里 Qwen／字節）或中國企業 agent 平台的低價競爭，而這正是全球模型推論掛牌價下行的重要外部推力之一（草稿 §3.2 自己點名「模型推論的掛牌價……一年來仍在下行」卻不解釋為何下行）。全文搜尋「中國」「DeepSeek」零命中。
- **草稿處理狀況**：無明文排除；邊界界定只排除「模型訓練與晶片層」與「消費端助理」，未排除地域範圍，屬於漏項而非刻意割捨。
- **建議補到**：mechanics §3.2（供給矩陣新增一列或一段）或 debates（作為第五張分歧卡：「中國低價模型是否會把應用層毛利假設壓垮」）。
- **建議查什麼**：DeepSeek/Qwen 等開源權重模型的企業採用率與定價、中國雲廠商（阿里雲/騰訊）agent 平台出海動作、模型推論掛牌價下行的供給面歸因（是競爭還是成本曲線本身下降）。

### D3. 需求方自供／超大型企業自建 agent stack
- **為何一階**：最大買家若完全繞開所有上市標的，直接決定可觸達市場的天花板；這與「開源編排層被採用」不同——是策略性 make-vs-buy 決策而非單純的免費工具選用，草稿把兩者混為一談。
- **草稿處理狀況**：§3.2 僅以「開源框架被財星 500 大採用」帶過，未區分「用開源元件自組」與「完全自建繞過所有覆蓋標的」；無案例、無比例數據、無明文排除。
- **建議補到**：mechanics §3.1（需求段補一小節）或 debates（併入分歧 1 的反方論證）。
- **建議查什麼**：大型銀行/政府/超大型科技公司自建 LLMOps/agent 平台的公開案例（如摩根大通、沃爾瑪內部工具）、企業調查中「自建 vs 採購」比例（Deloitte／Menlo Ventures 調查若有此拆分）。

### D4. 安全事件／資安風險（agent 自主操作的攻擊面）
- **為何一階**：草稿的核心護城河論證是「權限、稽核與紀錄住在哪裡」（分歧 1），但完全沒有討論這個護城河本身的脆弱面——agent 被授予高權限後的越權操作、prompt injection、資料外洩事件。一次重大資安事故足以同時影響採用速度（減緩）與監管態度（加速立法），是雙向風險，卻未進否證表也未進正文任何一段。全文搜尋「資安」「安全事件」「外洩」「injection」零命中。
- **草稿處理狀況**：無明文排除，純屬缺席。
- **建議補到**：risks §5（否證指標對帳表新增一條，或催化劑清單新增一項：「是否出現重大 agent 資安事故」）。
- **建議查什麼**：2026 年內已公開的企業級 agent 資安事故案例（若有）、資安廠商/研究機構對 agent 攻擊面的量化評估（如 OWASP agentic AI top risks）、企業導入 agent 時的資安審查流程是否已成為採用瓶頸之一（可能與 §3.1 的「治理摩擦」重疊但草稿未點名資安子項）。

## ③ 薄弱項（有提到但僅一句帶過、無數字或無判別訊號）

1. **勞動替代實證數據**——草稿的核心需求論證依賴「agent 真的在取代人力」，但直接證據只有 §5 否證表的「客服外包三家可比成長率中位數」這個間接代理指標；來源總表列了「Challenger, Gray & Christmas 裁員月報」（來源 #10，標註對應 §5），但本文正文（§5 全文含否證表、催化劑清單）完全沒有引用裁員月報的任何具體數字。等於一個一階證據來源被列進來源表卻沒有實際被使用，是「掛名未用」型薄弱項。
2. **模型推論成本曲線**——§3.2 一句話帶過「唯一接近成本曲線的變數是模型推論的掛牌價，而它一年來仍在下行」，§3.2 利潤池表也只以定性方向（↑/↓）呈現、無任何具體降價幅度或時間序列數據，卻是全篇對「應用層毛利能否守住」判斷的關鍵輸入變數之一。
3. **EU AI Act 監管深度**——只在來源表與催化劑清單各出現一次（生效日期＋二元 bull/bear 判讀句），沒有討論合規成本、agent 具體分類爭議（是否落入高風險附錄三類別的判準本身）、或除歐盟外其他轄區的監管動態，深度遠低於草稿宣稱的「造王者是監理與合規要求」這個論點應有的支撐力道。
4. **客戶集中度**——§6 個股表格列了各檔的「純度」（agent 收入佔比），但完全沒有討論這些 agent 收入是否集中在少數指標客戶（例如 Salesforce 的 Agentforce ARR 是否集中在幾家大客戶），這對一個「早期新品類」的收入曲線是否可持續是常見的隱藏風險，草稿未觸及。
