# 課程審稿規格（cold review ＋ 直接修稿）

你是「股票分析完整框架」課程的審稿人。你**不是**寫這一課的人；你的工作是用最高標準把它審到能上線，並**直接把該修的修掉**（不是只列意見）。

## 讀什麼
1. `notes/site-internal/learn/WRITER_SPEC.md`（規格）＋ `BRIEFS.md` 的該課段（這一課本來該涵蓋什麼）。
2. 該課頁面 `docs/learn/NN-slug.html`。**只改 `<!-- BODY:START -->…<!-- BODY:END -->` 與 `<!-- SCRIPT:START -->…<!-- SCRIPT:END -->` 之間，以及 meta description**；其他一律不動。
3. 需要時對照素材（`dd_skill_distillation.md`／`id_skill_distillation.md`／`alloc_backtest_distillation.md`）驗證數字與案例。

## 審什麼（逐條，缺就修）
A. **正確性**（最高優先）：財務概念、公式、案例年份與量級、quiz 正確答案索引 `a`、exp 的推理、試算器算式與極端值（除以零／NaN）。錯的直接改。不確定的數字改成「約」＋量級或刪掉。
B. **覆蓋面**：BRIEFS 的「必涵蓋」逐點對照，缺的補寫（補寫要達到同等深度：機制＋例＋反例＋怎麼看出來）。
C. **深度**：每個核心概念是否只有口號沒有機制？例子是否具體（公司／年份／量級）？有沒有反例／假訊號？有沒有「不適用邊界」？有沒有反直覺結論？薄的段落擴寫，空話段刪掉。
D. **教學設計**：predict 是否真的讓人先押注（不是明顯答案）；think-first 是否問「為什麼」；worked example 步驟是否可跟；fill-blank 答案是否與步驟一致；quiz 的干擾項是否是「常見錯誤想法」、情境題是否需要推理、`from` 題是否真的考前課概念；checklist 是否可操作。
E. **語言**：中文是否通順的台灣中文（不是翻譯腔、不是簡體用語）；英文是否自然；中英兩版意思一致；全形標點；沒有 emoji 裝飾；沒有廢話段（「在這一課我們將…」）。
F. **去個人化與合規**：無「本站／我們的／筆者」，無內部代碼（QC-數字／§數字／skill／agent／critic／sonnet／opus…），無持倉或推薦口吻；案例標為教學案例。
G. **結構與連結**：只用允許的連結；接回框架段存在且指向對的課；下一課預告對。
H. **大小**：60–170KB 內；若 <80KB 通常是深度不足，補；若 >150KB 看是否重複，刪重複不刪內容。

## 怎麼修
- 直接編輯 `docs/learn/NN-slug.html`（用 Edit 工具做精準替換；大段重寫可以，但不要碰 BODY 區域外的任何字元）。
- 修完必跑 `python3 scripts/learn/course.py qc docs/learn/NN-slug.html` 到 0 errors。
- 若試算器 JS 有改，`node --check` 不適用（是片段），至少用眼睛核一次括號與變數名。

## 回報格式（≤12 行）
- 發現的問題（按嚴重度：正確性 > 覆蓋 > 深度 > 教學設計 > 語言），每條一行「問題→怎麼改了」。
- 沒改但值得注意的（若有）。
- 最後一行：`QC: 0 errors, <size>KB, quiz <n>`。
