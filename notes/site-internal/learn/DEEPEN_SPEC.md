# DEEPEN_SPEC — 全課程「加深」二輪規格（2026-08-18）

適用：`docs/learn/01`–`29`（第 30–36 課案例庫依 WRITER_SPEC §9 新寫，不走本輪）。
執行：sonnet 寫手逐課改稿 → opus 冷讀審稿（REVIEW_SPEC ＋本檔 §5）。
起因：讀者回饋三條——「每堂課內容加深」「中文再淺白一點」「舉例用實際例子」。

## 1. 「加深」的定義（不是加長）

一課「夠深」＝每個核心概念都有**四件套**：
1. **機制**：不只說「是什麼」，追到「為什麼會這樣、靠什麼運作、什麼情況會壞掉」。
2. **正例**：真實公司／真實年份／真實數字（約＋期間＋出處類型），示範概念成立時長什麼樣。
3. **反例或假訊號**：真實案例，示範看起來像、其實不是；或工具在這裡失效。
4. **怎麼從公開資料看出來**：具體到「看年報哪一段／哪個科目／哪個公開網站／算哪個比率」，讀者明天就能自己動手。

其他深度標記（每課至少）：反直覺結論 ≥2 處；工具不適用邊界 ≥1 處；「動手做」練習 ≥1 個（fill-blank 或 worked example，含真實數字與解答）；試算器 ≥1 個且有極端值說明；quiz 10 題，其中情境遷移題 ≥5，`from` 交錯題保留。


## 1b. 最低配額（可量測；「原檔已經很完整」不是合格回報）

每課**必須**交出以下新增內容（新增＝原檔沒有的；審稿人會逐項點名）：
1. **每個概念型 h2 節新增 ≥1 個帶數字的美股真實例子**（公司＋年份＋數字＋出處類型），不可只補一句話，要有機制解釋（為什麼這個例子證明／推翻概念）。
2. **新增 1 個「動手做」練習框**：給讀者一家真實美股公司的公開數字（10-K／年報），要他自己算或判斷，附解答與解讀（用 fill-blank 或 `details.think-first`）。
3. **新增 1 個「公開資料在哪裡看」步驟框**：具體到哪份文件（10-K 哪一節／法說會哪段／哪個免費網站）、看哪個科目、怎麼算、正常範圍是多少、什麼數字是警訊。
4. **新增 ≥1 個帶數字的反例或假訊號**（看起來像、其實不是；或工具在這裡失效的真實案例）。
5. **每個既有 war-story／worked-example 加一層**：補「當時公開資料裡哪個數字已經露出訊號」或「這個判斷在什麼條件下會錯」。
6. **中文全課淺白化**（不是抽幾段），英文同步。
7. 淨篇幅：原檔 <150KB 者 **至少 +20KB**；150–170KB 者至少 +10KB；>170KB 者持平（先刪再加）。上限 190KB。

## 2. 改稿程序（寫手）

1. 讀 WRITER_SPEC（硬規則）、BRIEFS「## NN ·」段、該部素材（見任務單）。完整讀目標檔 BODY 區。
2. **先診斷再動手**：把本課每個 h2 節列成表——每個核心概念的四件套哪些有、哪些缺、哪些是泛論沒有數字。診斷表寫在 scratchpad（不進檔）。
3. **先刪後加**：刪同義重複、泛論式過渡段、沒有承載判斷的比喻，騰出篇幅。
4. **補四件套**：缺哪件補哪件。新加的例子一律真實可查證，**每個新數字先 WebSearch 查證**，文中寫「約」＋期間＋出處類型；查不到就不寫。**例子以美股（美國上市公司）為主；台股只用台積電**（讀者要求）。既有的非台積電台股例子，若有同類美股可換就換成美股，換不了才保留。
5. **中文淺白化**：所有 `.lang-zh` 段落——短句、一句一個意思、先結論後理由、專有名詞立刻白話（可用 `.key-term`）、少書面詞（其／之／所謂／亦／乃）、被動改主動、長定語拆句。**不改數字、年份、出處、結論方向**。
6. **英文同步**：英文版要有同等深度與同樣的例子（不是翻譯腔），中英段落一一對應。
7. quiz 補到 10 題（正解索引分散、≥5 題情境題）；試算器加參數說明或極端值。
8. 每改完一節就 inject 寫進磁碟並跑 `python3 scripts/learn/course.py qc docs/learn/FILE`；最終 0 errors、0 warnings。

## 3. 硬規則（不得違反）

- 只動 `<!-- BODY:START -->…<!-- BODY:END -->` 與 SCRIPT 區；skeleton 一個字元不動。
- 引號鐵律：`data-quiz`／`data-predict` 內不得有原生單引號（用 `&#39;`）。
- 全形標點；去個人化（不得出現 我們的／本站／內部／研究流程／持有人／團隊／我的／本人；不得出現站內裁決口吻、評級代號、內部欄位名）。
- 不做投資建議、不推薦個股。
- 不灌水：目標 150–185KB（QC 警告線 190KB）。加深＝把泛論換成機制與真例，不是把同一件事講三遍。原檔已 >150KB 的課，先刪再加，總量最多 +15%。
- 必交模組（試算器、worked-example、pitfall、war-story、takeaway、接回框架、quiz）全部保留。

## 4. 回報格式（≤10 行）

改了哪幾節、新增的真實例子（各附出處類型）、刪掉了什麼、最終大小、quiz 題數、qc 結果、自認最弱的一段。
