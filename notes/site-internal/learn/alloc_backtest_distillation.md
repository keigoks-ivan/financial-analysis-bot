## 1. 從一檔股票到一個組合

### 1.1 為什麼要分「指數部」與「個股部」

一個成熟的組合設計，不會只有「選股」一個環節。實務上可拆成兩個角色分工清楚的部分：

- **指數部（engine sleeve）**：用規則化、可回測、可驗證的機制驅動，負責組合的「引擎」——決定你在市場裡「有沒有曝險、曝險多少」。這部分刻意選擇流動性最高、最不需要個別判斷的標的（大盤型與產業型 ETF），把研究心力留給另一半。
- **個股部（stock sleeve / alpha sleeve）**：負責超額報酬的來源，容許主動判斷、深度研究、集中下注，但規模較小，虧損上限天生受限於配置比例。

範例配置：指數部占總股票曝險約 70%（由兩檔互補的 ETF 各半組成，例如一檔大盤型＋一檔產業聚焦型，用趨勢閘門 × 波動率目標化驅動，見第 2 節），個股部占約 30%（由核心持股與衛星持股組成）。**現金另計，約占總資產 8～10%，不算進股票曝險的分母**——這個「另計」很關鍵：現金水位是資產配置層級的決策，不應該被「指數部曝險目前只有 85%」這種訊號誤讀成「還有更多現金可以動用」。

### 1.2 為什麼指數部是引擎、個股是 alpha

指數部的角色不是「求表現」，是「求紀律的曝險節奏」——它替組合回答「現在該不該在場、該壓多重」這個最基礎的問題，且答案完全規則化、可回測、可驗證、情緒不介入。個股部才是回答「這個機會值不值得多下注」的地方，因為個股研究天生需要質化判斷，無法完全規則化。把「要不要在場」與「這一檔值不值得」拆成兩層決策，好處是：指數部出錯的代價有上限（規則錯了也只是全組合曝險節奏錯，不會因為單一個股判斷錯誤而放大），個股部的判斷錯誤也不會拖垮整個組合的市場曝險節奏。

### 1.3 部位角色 → 權重（core / satellite / tracking-only / not held）

個股部内部不是齊頭式平等，而是按角色分層：

| 角色 | 定位 | 典型權重 | 賣出邏輯 |
|---|---|---|---|
| **核心（core）** | 長期複利標的，護城河與 ROIC 持續期通過檢驗 | 較大、集中（例：5 檔左右構成核心） | 清倉需要「論點級」觸發（商業模式惡化、護城河趨勢翻轉），估值偏高或漲幅過大本身**最多只是減碼（trim），不是出場理由** |
| **衛星・結構型（satellite-structural）** | 高成長、跑道尚長的潛力倍數股，尚未達核心的信心門檻 | 較小、上限式（例：單一部位 ≤ 約 3%） | 論點觸發即可調整，門檻低於核心 |
| **衛星・循環型（satellite-cyclical）** | 有明確產業週期時機的提名標的（如半導體資本支出循環），靠位置錶族與反動能閘門把關進出場時機 | 較小、上限式 | 週期位置訊號驅動，非長抱邏輯 |
| **追蹤觀察（tracking-only）** | 只做研究與訊號追蹤、不投入實際資金的影子部位 | 0（唯讀） | 不適用；用於在真正上真金之前先驗證機制水下體驗 |
| **不持有（researched, not held）** | 做過研究但未通過裁決門檻 | 0 | — |

這個分層的核心紀律：**「值不值得投資」的最終判定不歸任何單一聚合層或篩選器**，一定要走過完整的研究到裁決鏈，聚合層／篩選榜單只回答「該看誰」，不回答「買不買」與「何時買」。名單本身不是收斂面，避免用「上榜」代替「做過決策」。

### 1.4 濃度限制與相關性群聚

只數「幾檔股票」會低估真實的集中度——如果三檔部位都是同一產業主題的不同載體（例如同一供應鏈上下游、同一個總經敘事的不同代理標的），它們對組合風險的貢獻高度重疊，實質上是**一個賭注**，不是三個。設計組合時應該：

- 用「主題／因子暴露」而非「檔數」來計算真實的分散度；
- 對同一主題的部位加總計算集中度，而不是逐檔獨立看待；
- 多個獨立聚合層（不同的篩選視角）對同一標的看法不一致時，這是**訊號不是矛盾**——分歧本身帶有邊際資訊（資格通過但動能降溫、或動能強但結構面未收斂，都值得回頭查原因），不需要「修到所有榜單一致」。

### 1.5 再平衡哲學

再平衡不是「定期把權重調回原設定」的機械動作，而是**由規則觸發，不是由日曆觸發**：

- 對於固定權重的組合骨架（例如兩檔指數各半），權重會隨市場漲跌自然漂移，**刻意不主動再平衡漂移本身**——回測與實作都不做「權重偏了就調回」這件事，因為那等於是在對抗趨勢。
- 真正驅動交易的是曝險引擎本身的訊號（趨勢閘門翻轉、波動率目標化算出的新目標曝險），而且只有變化幅度超過某個門檻才動手（見第 2 節「執行層」）——用門檻濾掉雜訊性的小幅調整，同時保留對真正 regime 轉變的反應能力。
- 個股部的「再平衡」則走論點觸發，不是估值觸發：核心部位漲多了不必然要賣，除非支撐論點的事實本身變了。

## 2. 趨勢閘門 × 波動率目標化

這是指數部engine的核心機制，設計目的是把「要不要在場」（閘門）與「在場的話壓多重」（曝險大小）拆成兩個獨立的、各自規則化的決策層。

### 2.1 機制逐步拆解

**第一層：趨勢閘門（binary gate）**

```
週線收盤 > 52 週均線（W52）→ 在場（gate = 1）
週線收盤 < 52 週均線（W52）→ 出場（gate = 0）
```

- 用**週線**（每週五收盤，W-FRI resample）而非日線判斷，理由：日線雜訊多，會製造大量假訊號與來回打臉的交易（whipsaw）；週線判斷把交易頻率壓到「一年個位數到十幾次」的量級，符合「長線、低頻」的設計初衷。
- 判斷後**向前填補（ffill）**到每個交易日，確保任何一天引用的都是「最近一個已知的週五收盤」，不是提前看到本週還沒收的資料——這是防前視偏誤的具體實作細節。
- 單線閘門（只用一條 52 週均線）比疊加多條均線斜率濾網更穩健——實測顯示加更多確認條件（見第 3 節），會延遲對 V 型反轉的反應，反而讓結果變差。

**第二層：波動率目標化（continuous sizing）**

```
曝險 = min(cap, σ_target / σ_realized)
```

- `σ_realized`＝近期已實現波動率（例：20 日已實現波動率，RV20）。
- `σ_target`＝波動率目標，**不是固定值，而是自適應**：取「近 3 年（756 個交易日）RV20 的滾動中位數」，且首年資料不足時用擴張視窗（expanding window）代替。**這是「自適應」的關鍵**——固定目標波動率（例如永遠設 20%）在結構性高波動標的上會長期低配（因為它的正常波動率本來就高於目標），自適應版本讓目標「跟著標的自身的近期常態」走，不再對高波動標的系統性懲罰。
- `cap`＝曝險上限（例：1.5，即最高可到 150%）——只有在市場**比自身近幾年更平靜**時（σ_target/σ_realized > 1）才會借錢加碼，波動一升高就自動降回甚至到 0（閘門關閉時強制歸零）。

**第三層：執行層（execution band，把訊號轉成實際下單動作）**

理論上曝險每天都在微調，但實務上頻繁下單／頻繁通知的摩擦成本很高。執行層的用途是把「連續的理論訊號」轉成「離散、稀疏的實際動作」：

```
若 |目標曝險(pp) − 現持曝險(pp)| < 門檻(pp)：不動作
若 ≥ 門檻：
    調整到目標曝險，並取整到最近的格點（例：10% 一格）
    取整後結果若超過上限，夾限（clamp）回上限
```

- 門檻與格點的比較**必須留在整數百分點（pp）空間做**，不能在 0~1 的浮點小數空間比較（見第 4 節規則 10）。
- **clamp 是必要的修正，不是可有可無的細節**：取整到格點可能把一個原本剛好在上限邊緣的目標，向上取整成超過上限的數字（例如目標 75%，取整到 10% 格會變成 80%，兩腿加總會讓組合曝險衝到 160%，超過原本設定的 150% 上限）。沒有夾限步驟，執行層會悄悄違反自己的風險預算。
- 執行層的加寬（例如把門檻從 10pp 放寬到 20pp、格點從 5% 放寬到 10%）**主要動機是降低調整頻率**（減少下單與通知次數），研究實測顯示這類調整能把每年調整次數降低約五成——但這是「摩擦成本的勝利」，不是「報酬率的勝利」，兩者必須分開陳述（見第 4 節規則 7）。

### 2.2 為什麼用週線而非日線

日線層級的趨勢確認系統，在缺乏額外過濾機制時做空勝率可以低到 10%多（遠低於隨機的 50%），且容易被短期雜訊反覆巴來巴去——在一段長期橫盤期，日線級別的子系統可以貢獻整個組合最大回撤的四分之三以上。週線判斷天生把交易頻率壓低、把雜訊濾掉，代價是反應變慢，但這個代價在多數情境下是划算的（見第 3 節的完整驗屍）。

### 2.3 為什麼上限設在 1.5 倍而非更高

曝險上限的選擇不是「越高越好」，理由有三層：

1. **真波動率目標化不是常態全速借錢**——即使上限設在 1.5，因為公式只在「比自身近期更平靜」時才借錢，實測平均曝險常落在 83～85% 左右，遠低於理論上限；風暴期會自動收槓桿到更低（例如某次金融海嘯分期的平均曝險只剩約 66%）。
2. **槓桿放大所有模型誤差**——樣本內迭代出的規則本身若有偏誤，槓桿會把偏誤等比例放大；深熊情境如果沒有在樣本裡出現過，槓桿下的行為就是未知數。
3. **實作管道的限制**——用融資（借錢買股）在某些市場的融資利率遠高於模型假設的借款利差，槓桿的增益會被融資成本吃光；正確做法是用期貨複製槓桿（保證金交易），且建議實際曝險峰值刻意壓在上限以下（例如上限 150% 時實際操作峰值控制在 140% 左右），留出保證金緩衝，避免市場劇烈波動時被強制平倉。

### 2.4 一個可重現的數字範例

假設某標的近期已實現波動率（RV20）＝18%，而其近 3 年滾動中位數波動率目標＝14%：

```
曝險比率 = 14% / 18% = 0.778 → 78%
若跨過執行門檻，取整到 10% 格 → 80%
```

假設同一標的進入一段異常平靜期，RV20 降到 8%（目標仍是 14%）：

```
曝險比率 = 14% / 8% = 1.75
夾限在上限 1.5（150%）→ 最終曝險 150%
```

這兩個數字合起來說明機制的完整行為：波動升高時曝險線性下降（去槓桿），波動降到目標以下時系統會借錢加碼，但借多少有硬上限。

### 2.5 範例回測結果（單一路徑，非績效宣稱）

在一組研究團隊測試的美股兩檔指數型 ETF 各半（2005 年至今）與台股兩檔標的各半（2014 年至今）配置上：

| 配置 | CAGR | 最大回撤 | Calmar | 年調整次數 |
|---|---|---|---|---|
| 美股組合，趨勢閘門×自適應波動率×cap 1.5×寬執行層 | 14.10% | −23.7% | 0.595 | 約 12.5 |
| 台股組合，同機制 | 22.98% | −18.9% | 1.217 | 約 12.3 |

這些數字**必須標註為「單一歷史路徑的回測結果」，不是保證未來報酬**——第 3 節與第 4 節會說明為什麼即使是這種「看起來很扎實」的頭條數字，都可能受到一個從未被當成自由參數處理的實作細節（例如「用週幾當作再平衡錨點」）嚴重影響，甚至左右方向性結論。

## 3. 已退役／已否決系統教我們的事

一套完整的方法論教育，不能只講「現在用的系統」，更要講「為什麼放棄了別的路」。以下每個系統都曾被認真設計、認真回測，最後被結構性地放棄或降級——放棄的理由本身就是教材。

**六狀態機（連續曝險狀態機）**：這是一個設計來取代「全進全出」二元閘門的方案，用五到六個狀態把股票曝險連續分級（例如從約 47.5% 到 95% 之間動態調整），理論上比二元閘門更精細。但它從未完成足夠的樣本外回測驗證就被結構上退役，改用更簡單、已經完整驗證過的趨勢閘門×波動率目標化引擎取代。**教訓**：額外的狀態複雜度必須先證明自己帶來「增量的、可驗證的邊際優勢」，才配拿到生產環境的席位；如果一個更簡單的方案已經有完整的樣本外證據支持，而複雜方案連驗證都沒跑完，複雜方案就該讓位——「少即是多」不是口號，是資源分配的紀律。

**雙軌系統的短線軌（日線級突破）**：原始設計是「短線軌（日線，占七成資金）＋長線軌（週線，占三成資金）」並行，理論上短線軌該提供額外交易頻率帶來的邊際報酬。真實 20 年數據顯示完全相反：短線軌的獲利因子只有 1.14～1.18（幾乎打平，扣成本後幾乎無 edge），做空勝率只有 11.8%～15.8%（遠低於隨機的 50%），且貢獻了系統史上最大回撤期間 75.7% 的虧損。**砍掉整個短線軌後，每一項指標同時變好**（CAGR、最大回撤、夏普、Calmar、交易數全部同向改善，統計學上稱為「柏拉圖完全支配」）——這是罕見但極具說服力的結果：**有時候最好的改善方式不是加一層濾網，是砍掉一整個子系統**。這個結論之後又通過參數敏感度測試（把週線參數在合理範圍內微調三組，CAGR 差距不到 0.5 個百分點，證明不是碰巧調到甜蜜點）與樣本外前進式驗證（訓練期夏普 0.71，驗證期夏普反而更高 0.94，排除過度擬合）雙重確認。

**Clenow 式分散化期貨趨勢跟蹤**：核心哲學是拒絕過度優化、接受多數年份表現平庸、靠少數大趨勢年份的爆發賺錢，且用「波動率加權部位」（依各市場的 ATR/波動率反向決定倉位大小）取代等權重。但一組研究團隊直接在自家的長多頭型動能引擎上測試「同一標的池內部改用反向波動率加權」，結果**沒有重現 Clenow 書中回撤壓縮的效果**：CAGR 中位數在全部測試配置中都變差，波動率確實降低但幅度小，風險調整後淨效果落在零到微負。診斷發現原因：Clenow 原始系統的回撤壓縮主要來自「總曝險會隨波動率浮動」（波動高時整體少壓、留現金），而這組研究團隊的引擎不管用什麼加權方式，**總曝險本身是固定滿倉的**——換權重只是在已選標的「之間」重新分配，不會降低組合對共同市場因子的曝險。當回撤是系統性的（相關性趨近 1，如金融海嘯或 2020 疫情崩盤），標的間重新分配救不了組合；唯一一次明顯有效的樣本窗口，是回撤本質上由標的間波動率離散度（而非系統性因子）驅動的情境（例如 2000 年網路泡沫，部分標的波動遠高於其他標的）。**教訓**：兩個「聽起來像同一件事」的機制（總曝險隨波動浮動 vs. 標的間風險平價重分配）其實是完全不同的槓桿，一個有效不代表另一個也有效，必須拆開驗證各自的邊際貢獻。

**海龜交易系統**：核心是 ATR 為基礎的部位規模化（讓不同市場的風險當量一致）、突破進場、反向突破出場（讓趨勢奔跑、不主觀判斷頭尾）。歷史績效期望值結構高度右偏——超過一半的交易是虧損的，獲利集中在少數能延續數月的大趨勢。**教訓**：edge 的來源不是提高勝率，是讓少數大贏家把整體期望值撐起來；最危險的執行風險是「連續虧損後選擇性跳過訊號」，因為統計上大趨勢往往緊跟在一串假突破之後，選擇性執行恰好會讓交易者躲過真正該抓住的那一筆。

**Alpha Architect 強健趨勢過濾（RTF）**：用兩個訊號（12 個月時序動能 + 12 個月均線）交叉確認，把資產曝險分成 100%／50%／0% 三段，而非全進全出的二元判斷。核心創新是那個 50% 的「訊號分歧」中間態——它不追求提高報酬，而是把最大回撤結構性砍半（歷史數據中標普 500 買進持有最大回撤約 −50%，疊加此機制後約 −24%，CAGR 幾乎打平甚至略升）。**教訓**：中間曝險狀態不是「優柔寡斷」，是刻意設計的震盪市避震器——它同時解決了「全進全出的來回打臉損耗」與「投資人心理執行率」兩個問題，因為極端的二元判斷在訊號模糊時最容易被投資人自己中途放棄執行。這類系統的定位通常是資產配置層的總體 overlay，疊加在個股／戰術層系統之上，而非取代它。

**GEM 雙動能（相對動能 + 絕對動能）**：核心邏輯是每月比較兩個股票資產池的過去 12 個月報酬，持有相對較強者，再用「該報酬是否跑贏無風險利率」做絕對動能濾網，濾網未過則轉入防禦資產。這套邏輯後來被延伸測試成「非股票資產（黃金／長天期公債／中天期公債／廣義商品）之間每月動能輪動」，作為股票組合以外的防禦性 sleeve 候選。結果**未通過預先設定的採用門檻**，被明確排除在候選名單外。**教訓**：一個在原始資產池（股票 vs 股票）上有理論基礎的機制，換一組資產池（非股票資產之間）不會自動繼承同樣的優勢，必須重新獨立驗證；而「不採用」本身是有效、值得跟「採用」同等重視發布的結論。

**部位規模軸消融研究**：這是專門檢驗「換一種部位規模分配方式（等權重 vs. 反向波動率 vs. 反向 ATR）能不能改善報酬」的系統性研究，見上方 Clenow 段落的診斷細節。它額外揭露了一個工程教訓：風險加權型的部位規模計算對資料品質高度敏感（某些標的因資料來源早期用固定價格回填、造成波動率算成 0，任何「除以波動率」的公式都會在這種情況爆掉），而等權重完全不受影響——這提醒設計者，越精細的規模化公式，越需要額外一層資料品質防呆。

**時機運氣審計**：這不是一個「策略」，而是一個「方法論校準工具」——見第 4 節詳細說明，核心教訓是「一個從未被當成自由參數處理的實作細節（例如用週幾當週線再平衡的判斷日）」可能比想像中更能左右結論。

## 4. 回測誠實性規則（約 14 條，附 WHY）

判斷一份回測研究是否可信，不能只看最後那個漂亮的 Calmar 數字。以下規則是從真實的錯誤與修正過程中提煉出來的檢查清單。

1. **一律用還原股價（total-return / split-and-dividend-adjusted price）計算報酬**。WHY：原始成交價遇到後續的股票分割或大額配息會產生尺度不連續，若不還原，報酬計算會嚴重失真（實測案例：若沿用發布當下的原始成交價當基期，遇到後來拆股的標的，報酬會算出離譜的錯誤數字）。

2. **明確揭露存活者偏誤（survivorship bias）**——若用「現行成分股」套用到更早的歷史區間，這是向上偏誤，必須標註，不能跟真正的時點正確（point-in-time）成分股資料混為同一等級的證據。

3. **杜絕前視偏誤（look-ahead bias），且要有可執行的驗證方法，不能只是口頭承諾**。具體做法：把某個歷史時點之後的價格資料人為改動（例如放大十倍），重新跑一次訊號與權重計算，確認改動時點**之前**的所有輸出逐格不變——這證明系統真的沒有偷看未來資料，而不是「應該沒有」。

4. **樣本外／前進式驗證（walk-forward / out-of-sample）是採用任何規則前的硬門檻，不是加分項**。把樣本切成訓練期與驗證期，只有當驗證期表現不明顯劣於訓練期（甚至更好），才能排除「規則只是在過去這段特定歷史裡湊巧好看」的疑慮。

5. **優化邏輯／結構，不優化參數**——動手回測前，先跟利害關係人討論方法本身（要不要加這個機制、這個機制的因果邏輯是什麼），而不是先跑一輪參數掃描找「最佳」數字。若必須检查参数敏感度，只能用來確認「結果穩不穩健」（一個平坦的參數響應曲面代表規則本質有效，而非湊巧踩到甜蜜點），不能拿來挑最佳參數。

6. **任何新增的規則、濾網、確認條件，都必須做消融測試（ablation），且允許測試結果是「這個方向無效，別做」**。加一個看起來更嚴謹的濾網，實測反而讓核心指標同時變差的案例是存在的（見第 3 節），而且一旦一個方向被驗證失敗，不應該在沒有全新設計的情況下重試同一個方向。

7. **嚴格區分「單一路徑的執行時點雜訊」與「真正的績效改善」，且不得把前者包裝成後者**。當一項改動的動機明確是降低交易頻率（摩擦成本），而它同時看起來也讓報酬指標變好，必須先確認這個報酬改善不是單純運氣（見規則 8 的審計方法），且明文禁止拿這個未經證實的報酬改善，去當作「所以應該進一步放寬同一類門檻」的理由——這是防止參數逐步擇優滑坡的關鍵防線。

8. **量化實作細節的敏感度（時機運氣審計）**——很多從未被當成「自由參數」處理的選擇（例如：週線用週幾當再平衡判斷日、月頻策略用每月第幾個交易日當成立日）其實是隱藏的自由度。系統性地把這些選擇換一輪跑過一次，看報告的頭條數字與方向性結論會不會受影響。真實案例：同一套規則換五個不同的週線判斷日，某個市場的 Calmar 比率全距可以達到相對均值三成以上，而**官方採用的那個判斷日恰好是五個選項裡數字最好看的一個**——不代表規則錯，但代表頭條數字本身帶有運氣成分，必須誠實揭露五個判斷日的分布而不是只秀最好的那個。

9. **交易成本／滑價必須顯性建模，且必須拆解「成本造成的差異」與「真實的機會成本差異」**。一個常見的誤判是看到兩個配置的周轉率不同，就直覺認為報酬差異來自成本——實測案例顯示周轉率差異造成的成本差往往只解釋整體報酬差距的一小部分（個位數百分比），剩下的絕大部分是真實的報酬取捨，不能全部賴給交易成本。

10. **離散門檻與取整規則的比較，一律在整數空間（百分點 pp、基點 bps、股數）做，不在 0~1 浮點小數空間做**。浮點誤差會系統性漏掉「恰好等於門檻」的觸發事件（`1.0 − 0.8` 在浮點下可能不精確等於 `0.2`，導致本該觸發的事件被跳過），這不是雜訊，是實作 bug，且影響方向通常是單邊的（系統性少觸發，不是隨機少觸發）。

11. **凍結規則與門檻（預註冊，pre-registration）**——設計定案後，把 W 視窗、σ 回望期、執行層門檻與格點這些數字寫死並公開凍結時間點，此後不因為看到某次結果不理想就回頭調整重跑。任何要調整的規則，必須先講清楚「什麼證據出現時，這條規則該被降級或撤回」（kill condition）——講不出撤回條件的規則不准新增。

12. **負面／無效結果要跟正面結果用同等篇幅、同等紀律發布**。「這個方向不值得採用」「這個資產不通過候選門檻」是跟「這個系統通過採用門檻」同樣有價值的產出，不能只挑好看的結果報告。同理，公開的長期戰績紀錄要做到「每一筆判斷都計入、不挑選、不事後刪除」，輸家與贏家並列呈現。

13. **報告分期／不同市場狀態下的表現，不能只給全樣本彙總數字**。一個漂亮的全樣本 Calmar 可能掩蓋「獲利集中在某一段特定行情、代價全部發生在另一段」的真相（例如：某規則的全樣本改善主要來自一段快速回升期的提早進場，代價則是在慢熊段的保護能力變弱）——只給全樣本數字等於藏起這個取捨。

14. **對照表必須確認是同條件比較（apples-to-apples）**。曾發生過一張「配置 A 優於配置 B」的官方對照表，實際上兩欄用的是不同版本的執行層規則，不是計算錯誤，而是表格語意上的疏漏，讀者容易誤讀成乾淨的單一變數對照——任何對照表發布前都要覆核「除了要比較的那一個變數，其餘條件是否真的完全相同」。

## 5. 回撤與風險預算

### 5.1 股票 sleeve 的最大回撤期望值

被動買進持有一組股票型 ETF（哪怕是分散在兩檔互補標的上），歷史最大回撤落在 −30% 上下是常態，不是例外——這是「承受市場系統性風險」本身要付的代價。即使是體質極佳的長期複利型個股，中途出現超過 50% 的帳面回撤也完全在合理分布內——**護城河與獲利能力沒有變壞，不代表股價不會經歷劇烈的估值壓縮**，這兩件事要分開判斷：回撤深度是市場情緒與利率環境的函數，論點是否還成立是基本面的函數，混為一談會導致「因為跌深就恐慌賣出體質未變的核心持股」或反過來「因為體質沒變就無視論點層級的警訊」兩種錯誤。

### 5.2 波動率目標化如何改變回撤的形狀

一個純粹的趨勢閘門（有訊號才在場，無訊號空手）已經能把最大回撤從買進持有的 −30% 級別壓到 −20% 級別。疊加波動率目標化之後，回撤的形狀進一步改變：**因為系統只在「比自身近期更平靜」時才借錢加碼，波動率一升高就自動去槓桿**，所以即使名目曝險上限設在 150%，實測平均曝險常常遠低於上限（八成多），且在真正的風暴分期（例如金融海嘯）平均曝險會自動收到更低。這代表槓桿上限本身不是「隨時頂格借錢」的承諾，而是「平靜期借一點錢加速複利，風暴期自動還原甚至空手」的機制——理解這一點，才不會誤以為「上限 150%」等於「隨時 150% 曝險」。

### 5.3 槓桿的數學：一個 −30% 的月份會發生什麼

槓桿的代價不是線性直覺能完全掌握的，需要具體算一次：假設某個月標的下跌 30%，在曝險 1.5 倍且尚未來得及去槓桿反應的情況下：

```
組合報酬 ≈ 1.5 × (−30%) = −45%
```

這比未槓桿版本（−30%）深了整整 15 個百分點，而且這還沒算進借款利差的額外拖累。**這正是為什麼「先驗證 1 倍版本的最大回撤有沒有留出安全邊際」是加槓桿前的必要步驟**——如果 1 倍版本的最大回撤已經壓縮到 −20% 級別（相對於買進持有的 −30% 級別已經改善了 10 個百分點），那麼加到 1.5～2 倍槓桿後的預期最大回撤，仍然有機會落在原始（未槓桿買進持有）能承受的回撤區間之內；反之，如果拿買進持有本身（−30% 級別）直接上槓桿，槓桿後的回撤會逼近甚至超過多數人能心理承受、甚至保證金能承受的邊界。**換句話說：低回撤系統的真正價值之一，是它替「要不要加槓桿」這個決策買到了安全邊際。**

同時要誠實揭露的代價：波動率目標化與執行層加寬會犧牲一部分「快速反應」的能力——面對一次極短時間內發生的急速崩跌（例如幾週內發生的系統性崩盤），較寬鬆的執行層會比較窄的執行層晚一步降低曝險，這個代價在實測中是可以量化到具體百分點的（一次歷史級的快速崩跌事件中，寬執行層版本比窄執行層版本多虧損了幾個百分點）。這不是機制的瑕疵，是「降低平時交易頻率」與「快速崩盤時的反應速度」之間必然的取捨，必須白紙黑字寫進系統說明，不能只講頻率下降的好處。

### 5.4 報酬順序風險（sequence risk）

同樣的長期年化報酬率，如果早期就先經歷一次深度回撤，對最終財富的侵蝕遠大於晚期才經歷同樣深度的回撤——這是為什麼「最大回撤有多深」比「長期平均報酬有多高」在資金規劃上往往更關鍵。一個回撤更淺的系統，即使長期年化報酬率略低於買進持有，仍然可能是更適合大額資金或槓桿疊加的骨架，因為它降低了「在最壞的時間點被迫縮減部位或失去執行紀律」的機率。

## 6. 給互動計算器用的公式與數字

以下是可以直接拿去做教學用計算器／模擬器的公式，均取自真實回測引擎的實作邏輯。

**曝險公式（波動率目標化）**
```
曝險 = min(cap, σ_target / σ_realized)
若閘門關閉：曝險 = 0
```
- `σ_realized`：近 20 個交易日已實現波動率（年化）
- `σ_target`：`σ_realized` 過去 756 個交易日（約 3 年）的滾動中位數，前 252 天不足時用擴張視窗
- `cap`：曝險上限（教學情境可設 1.0／1.25／1.5／2.0 讓學員比較）

**趨勢閘門**
```
gate = 1 若 週收盤 > 52週均線；否則 gate = 0
最終權重 = gate × 曝險
```

**執行層（門檻＋取整＋夾限）**
```
輸入：target_pp（目標曝險，百分點）、executed_pp（現持曝險，百分點）
若 |target_pp − executed_pp| < 門檻pp：
    輸出 = executed_pp（不動作）
否則：
    rounded = round(target_pp / 格點pp) × 格點pp
    輸出 = clamp(rounded, 0, cap × 100)
```
教學情境可讓學員切換「門檻 10pp / 格點 5%」vs「門檻 20pp / 格點 10%」，直接比較兩者的模擬調整次數與模擬曝險路徑差異。

**槓桿回撤數學**
```
單期損失(槓桿) ≈ 曝險倍數 × 單期損失(現貨) − (曝險倍數 − 1)⁺ × 借款利差 / 期數
```
教學情境：輸入現貨跌幅（例如 −10% / −20% / −30%）與曝險倍數（1.0～2.0），即時算出槓桿後損失，讓學員直觀感受「槓桿不是把報酬乘以固定倍數，是把損失也乘以同樣倍數」。

**核心／衛星權重建構器**
```
股票總曝險% = 指數部% + 個股部%
個股部% = 核心檔數 × 平均核心權重% + 結構型衛星檔數 × 衛星上限% + 循環型衛星檔數 × 衛星上限%
總資產 = 股票總曝險% × (1 − 現金比例%) 換算後的絕對配置
```
教學情境：讓學員拉桿調整「核心檔數／衛星上限／現金比例」，即時看總持股數與最大單一產業暴露的變化。

**相關性群聚（有效獨立賭注計算器）**
```
有效獨立賭注數 = Σ(1 / 該主題群聚內檔數)，對每一檔加總
```
（例：5 檔分散在 5 個不重疊主題＝5 個有效賭注；5 檔中有 3 檔屬同一主題＝有效賭注數降到約 3）。教學情境：讓學員輸入持股清單與各檔的主題標籤，計算器輸出「真正的分散度」而非表面檔數。

**風險調整報酬指標**
```
Calmar 比率 = CAGR / |最大回撤|
Sortino 比率 = (CAGR − 無風險利率) / 下行波動率
Martin 比率（Ulcer Performance Index）= CAGR / Ulcer Index
```

## 7. 案例故事（已去個人化）

1. **合成組合淨值時直接相加，而非用報酬率加權**。一組團隊把兩條獨立的百萬元起始淨值曲線直接數字相加，而不是先各自算報酬率再依權重合成——這個算法錯誤讓某一年的最大回撤被誇大到 −25.6%，修正後不僅數字改變，連「哪一年才是真正最深的回撤」這個結論本身都變了。**教訓**：組合層級的淨值合成，永遠用報酬率加權，不要用金額直接相加，即使兩條曲線起始金額相同也一樣。

2. **一次流動性濾網嘗試以失敗告終，且被明確記錄「別再試同一個方向」**。一組團隊嘗試加一個「市場流動性緊縮時停止新進場」的濾網，退場條件設計得太嚴格，導致濾網在某段時期之後永久保持啟動狀態，結果是年化報酬損失兩位數個百分點，換來的回撤改善卻微乎其微。這次失敗被明文記錄下來，並附帶一條規則：不要在沒有全新規則設計的情況下重新嘗試同一類濾網。

3. **一個「聽起來能分散風險」的日內快速交易子系統，貢獻了系統史上四分之三的最大回撤**。它的設計初衷是用更高頻率的訊號補強一個低頻長線系統，實測卻發現它的做空勝率遠低於隨機水準，且貢獻了系統史上最深回撤期間絕大部分的虧損。移除整個子系統後，剩下的低頻系統在每一項指標上都全面改善——有時候最好的優化不是加一層，是砍掉一整層。

4. **一個「看起來更嚴謹」的額外確認條件，讓系統同時變差**。一組團隊測試在既有的趨勢確認規則上再疊加一條更嚴格的斜率確認，直覺認為會過濾掉更多假訊號。回測結果卻是報酬與回撤同時惡化——因為原始規則的優勢部分來自對 V 型反轉的快速反應，額外的確認條件延遲了進場，恰好錯過了系統賴以獲利的那類急速回升行情。

5. **一個借鏡知名趨勢跟蹤書籍的風險平價部位規模化方案，換了資產池就沒有複製出原書效果**。研究團隊原本預期「標的間按波動率反向加權」能像原書描述的那樣壓縮回撤，實測卻發現淨效果幾乎是零到微負。深入診斷發現原因：原書的回撤壓縮主要來自「總曝險隨市場波動浮動」，而這組團隊的引擎不管換哪種加權方式，總曝險本身都是固定滿倉的——換權重只是在標的之間重新分配風險，並沒有真正降低組合對系統性回撤的暴露。**先診斷機制、再談要不要採用**，避免把一個沒有淨效益的改動誤判成「複製失敗只是參數沒調好」。

6. **一項降低交易頻率的執行層調整，意外讓某個市場的風險調整報酬指標看起來變好，但審計揭穿那是運氣**。一組團隊把執行層門檻放寬以降低下單頻率，副作用是某個市場的 Calmar 比率也跟著上升。專門設計的敏感度審計——把「用週幾當週線判斷日」這個從未被當成自由參數的選擇換了五輪跑——發現在另外四個判斷日選項下，同樣的調整反而讓 Calmar 比率下降；唯獨「官方採用的那個判斷日」剛好是報酬改善的那一個。團隊原本就有一條自律規則，聲明「執行層調整帶來的報酬指標變化屬於雜訊，不能拿來當績效宣稱」——這次審計證明了那條自律規則從一開始就是對的。

7. **一張官方對照表悄悄比較了不同條件的兩欄數字，不是算錯，是表格語意有缺口**。一份被廣泛引用的槓桿對照表，把「新版執行層規則的 1.5 倍槓桿」跟「舊版執行層規則的 1 倍槓桿」並排放在同一張表，粗看像是乾淨的槓桿對照，實際上比較的兩個配置有兩個變數同時不同。這種錯誤不容易靠肉眼抓到，因為每一欄自己的數字都是對的，問題出在讀者會不自覺假設「除了要比較的那個變數，其他都一樣」。

8. **一個非股票防禦性資產輪動候選，在預先設定好的門檻下被明確否決，且照樣公開發布**。一組非股票資產（黃金／公債／廣義商品）之間的每月動能輪動機制，被拿來測試能否加入組合當防禦性 sleeve。它沒有通過事前凍結的採用門檻，最終結論是「不建議採用」，且這個否決結論跟其他通過門檻的候選資產一樣，用同等篇幅公開發布——負面結果跟正面結果享有同樣的發布紀律。

9. **一次執行層加寬的代價，在最極端的一段快速崩盤裡被具體量化出來，而不是只講平均意義下的好處**。一套已採用的系統把執行門檻加寬以降低調整頻率，好處在多數情境下確實成立，但團隊也主動計算了在一段歷史級的急速崩盤窗口裡，加寬版本比原始版本多虧損了幾個百分點——因為較寬的門檻讓系統在快速崩盤中晚了一步降低曝險。這個代價被寫進公開說明，而不是只強調「調整次數降低五成」這個對系統有利的一面。

10. **一份公開的長期戰績頁，原本會因為股票分割而把報酬算錯，後來修正為一律用還原基期計算**。原始設計用「報告發布當下的實際成交價」當作報酬計算的起點，後來發現如果某檔標的在報告發布後經歷股票分割，用原始成交價當基期會讓報酬率算出離譜的錯誤數字（因為分割前後價格尺度不同）。修正方法是一律改用「發布日當天或之前最近一個還原收盤價」當基期，確保基期與後續追蹤的報酬在同一個價格尺度上可比。

|---|---|---|
| Trend gate | 趨勢閘門 | 二元判斷「在場／出場」的規則層，通常基於價格相對長期均線的位置 |
| Volatility targeting | 波動率目標化 | 依當前波動率相對目標波動率的比值決定曝險大小 |

| Calmar ratio | 卡瑪比率 | 年化報酬率除以最大回撤絕對值，衡量單位回撤換得的報酬 |
| Sharpe ratio | 夏普比率 | 超額報酬除以總波動率，衡量單位波動換得的超額報酬 |
| Sortino ratio | 索提諾比率 | 類似夏普比率，但只用下行波動率當分母 |
| Martin ratio (Ulcer Performance Index) | 馬丁比率（潰瘍表現指數） | 年化報酬率除以潰瘍指數，比最大回撤更能反映回撤的持續時間與深度 |
| Max drawdown (MDD) | 最大回撤 | 從歷史高點到隨後最低點的最大跌幅 |
| Walk-forward test | 前進式驗證 | 把樣本切成訓練期與驗證期，依序驗證規則在未見過的資料上是否仍然有效 |
| Out-of-sample (OOS) | 樣本外 | 未被用來設計或校準規則的資料區間 |
| In-sample (IS) | 樣本內 | 被用來設計或校準規則的資料區間 |
| Overfitting / curve-fitting | 過度擬合 | 規則被調整到剛好適配特定歷史資料，缺乏普遍有效性 |
| Look-ahead bias | 前視偏誤 | 回測中意外使用了在該時點還不存在的未來資訊 |
| Survivorship bias | 存活者偏誤 | 只用「後來存活下來」的標的或公司做歷史分析，高估歷史表現 |
| Ablation study | 消融研究 | 逐一移除或加入單一機制，量測其獨立貢獻的實驗方法 |
| Pre-registration (prereg) | 預註冊 | 在看到結果之前，先公開凍結規則與判準，禁止事後回頭調整 |
| Kill condition | 撤回條件 | 一條規則被撤回或降級所需的具體、可驗證的證據標準 |
| Timing luck | 時機運氣 | 因為選擇了某個特定但任意的實作時點（如再平衡錨點）而產生的績效差異 |
| Single-path noise | 單一路徑雜訊 | 單一歷史路徑下觀察到的數字波動，未必反映真實、可重複的效果 |
| Core / satellite portfolio | 核心／衛星組合 | 把組合分成集中持有的核心部位與規模較小、彈性較高的衛星部位 |
| Correlation clustering | 相關性群聚 | 多個標的因共享同一主題或因子而高度相關，應視為一個風險單位 |

| Cross-sectional risk parity | 橫斷面風險平價 | 在同一組候選標的之間，依各自波動率反向分配權重 |
| Absolute momentum vs. relative momentum | 絕對動能 vs. 相對動能 | 前者比較標的自身報酬與無風險利率，後者比較多個標的之間誰的報酬較強 |
| Dual momentum | 雙動能 | 同時使用相對動能（選標的）與絕對動能（決定要不要在場）的策略框架 |

| Turnover | 周轉率 | 一段期間內部位變動的總量，通常用於估算交易成本拖累 |
| Slippage | 滑價 | 實際成交價與理論訊號價之間的落差，通常因流動性或延遲造成 |
