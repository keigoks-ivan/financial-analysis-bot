# 後續小任務：把中文版的「（十億美元）」單位標籤改成「億美元」（2026-08-19）

## 為什麼
中文版有些表格欄位、試算列、填空題把單位寫成「十億美元」（直譯自 $ billion）。台灣讀者的習慣單位是「億美元」，同一頁的內文也已經在用「63 億美元」「820 億美元」，只有這些欄位標籤還是「十億美元」，讀起來突兀又不一致。

**注意：「數十億美元」「好幾十億美元」是正常中文（billions of dollars），一律不要動。** 只改「當成計量單位的欄位／答案標籤」。

## 要改的位置（僅中文 lang-zh，英文不動）
- `docs/learn/03-demand.html`：266、270、282、286、406（2 處）、408、422、443
- `docs/learn/05-profit-pool.html`：286、288、289、348、362、369、383
- `docs/learn/33-case-uber.html`：295、307、324
- `docs/learn/34-case-ge.html`：265、266、267、268、269
- `docs/learn/35-case-nextera.html`：231、232、396

（行號以 2026-08-19 潤稿後的版本為準，實際請用 `grep -n 十億美元` 重新定位。）

## 怎麼改
1. 單位標籤「（十億美元）」→「（億美元）」。
2. **同一個表格／試算／填空裡出現的所有數值一律 ×10**（因為 1 十億 = 10 億）。包含：
   - 內文敘述裡跟這個單位配套的數字（例：`280（十億美元）` → `2,800 億美元`）
   - `<input class="fb-input" data-answer="...">` 的 `data-answer` 值（例：126 → 1,260）；`data-tol` 也一起 ×10
   - 表格 `<td>` 內的數值、`data-echo` 預設值、calc 滑桿的 `value/min/max/step`（若該滑桿的單位是十億美元）
   - **JS 計算式**：若 `<script>` 裡有對應的係數或輸出格式，必須同步調整，否則試算結果會差 10 倍。改完務必在瀏覽器或用 node 心算驗一次輸出數量級。
3. ≥4 位數加千分位逗號（2,800 億美元）。數字與中文之間留半形空格。
4. 英文版的 `$ billion` 與英文那一份 `data-answer` **完全不動**。

## 驗收
- `python3 scripts/learn/course.py qc docs/learn/<檔名>` → 0 errors
- `grep -n '十億美元' docs/learn/<檔名>` 只剩「數十億美元」這類敘述性用法
- 手算一次每個 `data-answer`：用改後的中文題目數字算，答案要對得上

## 2026-08-19 決議：不做 ×10 換算，改為單位標籤數字化

原計畫「（十億美元）→ 億美元、所有數值 ×10」**未採用**。原因：

1. `calc-card` 的 slider（`<input type="range">`）與 `data-echo` 是 **EN／ZH 共用同一個 DOM 元素**，值改了英文版會跟著錯。用戶指令是「中文的不要管英文」，不得動英文。
2. worked-example、fill-blank、calc-card 三處的數字互相對照（例：`280 ÷ 140 = 2.0x` 同時出現在推導與試算器）。只改一部分會讓三處互相打架，對初學者更難懂。
3. 這是一門講數字的課，算術被改壞的代價遠高於單位用詞的美觀。

**實際採用**：`十億美元` → `10 億美元`（純單位標籤數字化，所有數值不動）。既滿足「金額用阿拉伯數字」，又零算術風險。共 26 處，涵蓋 03／05／33／34／35。

`百萬美元` **維持不動** — 台灣財報標準單位用法（「單位：百萬美元」），本身不是中文數字寫法。唯一例外是 `04-supply.html` 的 `8,386 百萬美元 / 7,698 百萬美元`，因為那是「數值＋單位」而非表頭標籤，已改為 `83.86 億美元 / 76.98 億美元`（比率 1.09 倍不變）。
