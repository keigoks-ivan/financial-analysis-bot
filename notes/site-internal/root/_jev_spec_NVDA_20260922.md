# 交給 Jev 的決策層規格（NVDA 示範）

日期：2026-09-22。取代同日主張樹備忘裡第三、四節我自己填的答案與機率。樹的結構（六根支柱、主張句、輕重標記）不變。

## 一、分工改成這樣

- 我出題。每條主張寫成一題英文問題，附答案選項和每個選項的邊界。題目放在 `scripts/jev/questions_NVDA.json`，一個檔案全部看完。
- Jev 答題。每天把當天新聞餵給它，它對每題回一個固定型別的答案：三選一加信心，或是非機率。它只判「證據裡有沒有」，不預測未來。
- 程式合成。數字類主張程式自己算，Jev 的答案套規則表，出支柱狀態和判決。
- 人補洞。Jev 信心不夠的送 Opus 複核，再不夠的進人工待辦。

## 二、32 條主張誰來答

| 誰答 | 條數 | 例子 |
|---|---|---|
| 程式算數字 | 15 | FY28 共識下修幅度、FCF 利潤率、PEG、收盤對支撐 |
| Jev 讀新聞 | 16 | 實驗室訓練轉單、MI450 用途、Rubin 延誤、四大資本支出、六條風險 |
| 人工查 | 3（跟 Jev 重疊） | CoWoS 配額、市占估計、客戶投資回流比例 |

原本 37 條併掉 5 條。五條「不知道的事」不出題，只列出什麼時候會變成查得到。

## 三、題目怎麼出（照官方文件的坑寫的）

- 用英文。官方說中文準確度較低。中文只留在顯示欄位。
- 每題只問「新聞裡有沒有這件事」，不問「會不會發生」。預測不是 Jev 的事。
- 數字、日期、門檻全部留在程式。市占那題不叫它比大小，改成四個區間讓它選。
- 本業主張用三選一：撐住、翻掉、沒相關證據。日常新聞多半是第三個，三選一才拿得到信心值。
- 風險主張用是非題，問「已經發生了嗎」。演習、傳聞、分析師情境在邊界裡明寫算否。
- 每題的選項邊界寫具體。官方說它讀字面，不猜你的意思。
- 送給 Jev 前先過一道相關性篩選，一則新聞一題是非，不相關的丟掉，減少干擾。

## 四、答案怎麼用（門檻是起點，要靠紀錄修）

| 答案 | 信心 | 程式做什麼 |
|---|---|---|
| 翻掉 | 0.85 以上 | 主張改成否，通知 |
| 翻掉 | 0.6 到 0.85 | 送 Opus 讀同一批新聞複核 |
| 翻掉 | 0.6 以下 | 進人工待辦 |
| 撐住 | 任何 | 記「最近一次確認日」 |
| 沒相關證據 | 任何 | 不動 |
| 風險已發生 | 機率 0.9 以上 | 立刻通知人，不自動歸零支柱 |
| 風險已發生 | 0.5 到 0.9 | 送 Opus 複核 |

風險支柱歸零一律要人點頭。這是不可逆的判決，不交給模型信心。

## 五、先跑影子模式，不接正式檔

1. 拿到 API key 後跑三個測試包：平常日、應該翻掉的日子、模稜兩可的日子。看題目有沒有問對。
2. 題目穩了，每天真的餵新聞，答案只記在 `scripts/jev/probe_log.jsonl`，不改 stock-dash 的判斷。
3. 人工每週對一次答案，累積三個月，看每題在各信心區間的命中率，再決定門檻和哪些可以自動。
4. 模型版本釘 jev-1.13.0。換版要重跑測試包。

## 六、費用

每次請求約 2,000 到 5,000 個輸入 token，每百萬 0.042 美元。339 檔每天跑一次，一個月不到 2 美元。成本不是問題，新聞來源才是。
