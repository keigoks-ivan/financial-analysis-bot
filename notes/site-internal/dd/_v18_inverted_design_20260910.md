> - 每檔固定回答核心問題：怎麼賺錢、競爭優勢、成長、現金與資本配置、估值、可能看錯在哪。

## 一、六個核心問題的最小交付物

**結論：六問是每檔必答的問題，不是每家公司填同一組數字。**下列是預設交付物、不是上限，表格是需要時的產物、不是入場費。**特殊公司換尺（archetype 路由）優先於本節**——金融、未獲利、循環、轉機各有自己的尺，別讓「每題一句」變成新的品質天花板。

1. **怎麼賺錢**——營收分部與最新一季毛利／營益率（法說親讀＋10-K／10-Q）；判斷句＝賺誰的錢、錢卡在哪一節點。>10% 只是預設起點，**未達 10% 的分部若是新增利潤或風險核心，照樣展開**。不預設 TAM／SAM／滲透率表。
2. **競爭優勢**——一條機制（不是清單）＋一個可證方向：對最強同業的 ROIC spread 或最大客戶份額方向，附 12 個月內 sourced data point；判斷句＝`moat.trend`。ROIC 同業差不是每種生意都取得得到或可比，取不到就換一個可比的軸並說明為什麼換。同業財務對照只在該方向是爭點時展開。
3. **成長**——量、價、併購還是回購；三年共識 EPS CAGR（標家數與來源）＋內生上界（ROIIC × 再投資率，**全份唯一推導處**）＋缺口歸因一句；判斷句＝`runway_post_y5`。
4. **現金與資本配置**——FCF／NI 轉換率、SBC／營收、近三年現金去向四分、債務到期與利率；判斷句＝`capalloc_grade`。十年併購全史只在連續收購型或本期有重大交易時展開。
5. **估值**——`peg`／`percentile_5y`（估值燈與 screener 直讀）＋情境樹三支的 EPS 路徑、終端倍數、機率；判斷句＝現價要求未來 X 才划算，我信不信。IRR／EV5Y／AR 由情境樹機械算；**Max DD 不是機械算**，見 §四。
6. **可能看錯在哪**——`premortem.blind_spots[]` 三視角各一條以上（論點失敗／論點成功但股東經濟變差／價格已反映太多），每條帶 `evidence`／`assumption`／`consequence`／`ruling`／`watch`。**全份唯一反證居所**；steelman、trap 依據、`plain.fears` 引用不重寫（WP-D A1）。

## 二、疑點怎麼定義、誰來提

**結論：疑點由判斷者提，機械敏感度最多是提醒清單，不是研究範圍的排除器。**

**定義**：疑點＝**尚未釐清、有合理可能性的事實或假設，且它會影響商業論點、估值或行動（三者任一）**。不是「單欄擾動會翻 verdict」。

**為什麼撤掉 r1 的機械定義**（Codex 以 `dd_decision.evaluate()` 合成輸入實測）：

- **單變量看不見聯合效果**——`signal=C`＋`runway=紅` 時，單獨改 signal 或單獨改 runway 都仍是「觀望」，兩項同時改善才變「進場」。真正的疑點常常是兩三件事一起動。
- **會造出假問題**——把已經充分排除的 thesis 失效 bool 機械翻成 true，裁決當然會變，卻不代表那件事值得再查。±20% 也不是資料不確定性的通用範圍，衍生欄逐欄亂動還會造出內部不一致的假情境。
- **會漏掉真問題**——`capalloc_grade` A→C 裁決同樣是進場，持有上限卻從無上限掉到中期 2–5 年。**持有人在意的報酬幅度、下行風險、角色與持有條件，不一定改變三選一標籤。**新標的更沒有前份漂移可用，(b)(c) 兩個補抓訊號也不成立。

**怎麼保留**：機械敏感度若日後仍要跑，它的產物是**給判斷者的提醒清單**——可採納、可略過，略過不必舉證；既有 gate（Stage 1G）發現判斷者沒看到的疑點時可補提。**不建多變量搜尋引擎**：修單變量的缺陷不是換成組合爆搜，那是用更複雜的程序去管理複雜的程序。

**條數**：0–4 是**單批工作量目標**，不是最少配額，也不是關鍵疑點的硬截斷。零疑點合法且常見；真的超過 4 條，就在 `judgment.json` 裡揭露「還有哪些沒收斂」，不准默默丟掉第五條。

## 三、流程形狀：預設一次判斷，補查是例外

**結論：基準版不新增任何循環。**現有 Stage 0 獨立採集 →**一次**精簡判斷（Fable）→ 既有 opus 閘 Stage 1G → 快速版渲染。stage 名稱、`gate_view` 抽取面、三支 validator 全不動。

本輪唯一改的是**判斷段要寫多少**（§一 交付物精簡＋§六 schema 瘦身）。**Stage 0 的輪數與批次密度不在基準版內**——那是改採集流程，風險與寫作量精簡完全不同，須先過 §七 第二層驗證才准動。

**例外分支｜補查**（不是每檔都跑）：判斷者在 `judgment.json` 標出「**缺資料且可能實質改變結論**」的疑點時，才追加**一次**定向搜尋。規則四條：

- 搜尋 agent（sonnet）收到的是問句與「要什麼證據才能定」，**不收到既有判斷**（防錨定）。
- 產物**必須併回 `evidence.json` 的 coverage**，否則新查到的負面證據落在 J1 掃描面外。
- 回來後**只更新受影響欄位**與其連動的機械投影，不整包重寫。
- 補查最多一次；仍未結案走 §五 第③類（`undecidable`）。

**零疑點可直接完成**，不需要為了「有跑過流程」補一輪。

**基準（一次判斷）vs 加草判機制**：r1 的甲案（先草判 → 機械算疑點 → 深查 → 定稿）**降為候選增量**，不是預設。乙案（單一 agent 帶搜尋工具邊查邊判）仍不採，但理由收窄——單一 agent 不必然等於沒有結構化 `evidence.json`，獨立 sonnet 也一樣可能漏查負面事實；獨立採集真正的價值是**採集紀律**（`source`／`as_of`／`queries_run`／`direction` 是 validator 逼出來的）與**可稽核的外部對照面**，**不是「保證不漏負面證據」**：J1 只能檢查已收錄的負向證據有沒有處置，證明不了未知的負面證據不存在。

**成本**：r1 的「甲 $11–13／乙 $15–25」與現行 $16.2 的對比**全是未驗證預估，不作選型證據**。量測順序＝**先量基準（只精簡內容、維持一次判斷），再量草判機制的增量**；只測整包會不知道是哪些改動在省錢、哪些在花錢。

## 四、不能省的清單，各自放哪

**結論：以下八項全部原位保留，一項都不移進條件式。**

- **來源與 as-of**——留在 coverage finding 契約、`validate_evidence.py` 硬擋；精簡寫作量不降舉證標準。
- **負向證據處置（J1）**——`validate_judgment.py` 不動；補查產物必須併回 `evidence.json`（§三）。
- **數字一致性**——`dd_scenario`／`dd_decision`／`validate_judgment`＋`verify_dd_math`（已含 `BRIEF_*.html`）不動；改路徑或預設產物時逐一點名這四道加 pre-commit。
- **跨模型閘 Stage 1G**——位置、模型、嚴格度不動；契約同步（閘問的與機械層驗的是同一件事）已於 WP-E 完成。
- **`decision_inputs` 22 欄與決策矩陣**——完全不動。
- **dd-meta 下游欄位**——`dca_role`／`ev5y_pct`／`irr_base_pct` 由情境樹機械投影；`peg`／`percentile_5y`／`val_light` 判斷 agent 必交，**永不進條件式**。
- **Max DD 的判斷依據**——`dd_metric_resolver.resolve_max_dd_pct`（58–66 行）**只是讀 `premortem.max_dd` 的 lo／hi 取下界**，不像 IRR 那樣由情境價格推出來。lo／hi 是**判斷輸入**，回撤範圍的推導依據必須留在 `premortem`，不得以「機械算」為由降 optional 或省掉理由。
- **特殊公司換尺**——archetype 路由與 gate-set 不動；金融／未獲利／循環／轉機不套一般模板。

## 五、停止規則與「尚不能裁決」的下游行為

**結論：停止綁在疑點結案狀態，不綁篇幅、不綁表格數；但「停止搜尋」不等於「可以裁決」。**

**三分類**（取代 r1 的兩分類——那版依字面會讓重要缺口以「取不到，維持不確定」結案後，照樣發出普通的進場裁決）：

| 分類 | 意思 | 出口 |
|---|---|---|
| ① 已釐清 | 拿到能改變答案的證據並落進 judgment | 正常裁決 |
| ② 缺資料，但合理範圍內不影響結論 | 查不到，且各種合理取值都不翻結論 | 正常裁決＋在 judgment 註明缺什麼 |
| ③ 缺資料，且可能實質改變結論 | 合理取值範圍會翻結論，或翻角色／持有條件 | **即使已停止搜尋，仍標 `undecidable`** |

停止條件＝清單每條都歸入①②③其一，且三支機械驗證與 J1 全過。

**旗標方案（維持 r1 的預設）**：`dca_verdict` 落「觀望」＋dd-meta 選填 `undecidable=true`／`undecidable_reason`，`rearm_trigger` 填缺的那條證據，brief 頁首顯示「尚不能裁決（暫記觀望）」。**但 r1 說「下游三處皆不受影響」是錯的**——暫記觀望不會被任何消費端自動排除，五個消費端必須逐一決定：

| 消費端 | 預設處理 | 理由 |
|---|---|---|
| **engine 候選／席位**（`scripts/engine/build_arena.py` 行 333 現只對「迴避」veto） | **不排除**，看板該列加「研究未完成」標；`dd_fresh`／`role_mismatch` 一律視為無角色資訊、不做 mismatch 判定 | v3 席位資格已不要求先有 DD（2026-09-09 拍板），資格綁品質閘與三年成長；一份沒判完的 DD 不該比「完全沒有 DD」更不利 |
| **picks 爆發榜**（`scripts/build_picks.py:396` 只把 verdict 當註記顯示） | **不排除**，註記顯示「觀望（研究未完成）」 | 入榜條件是修正動能與守門、不吃 verdict；發現層本來就不是收斂面，硬擋只會少看一個名字 |
| **dd-screener 燈號**（`scripts/build_dd_screener.py` 三級門檻） | **一律無標記**：◆ 本就要求 `dca_verdict=進場`故自然落空，★★／★ 需**新增一行**明確排除 | ★ 級門檻只看 ar／IRR／trap 不看 verdict，而 undecidable 的意思正是「這些數字所依據的假設還沒站穩」，掛星等於用未定案的輸入發不對稱訊號。**五個消費端裡唯一要動程式的一處** |
| **校準統計**（`scripts/build_track_record.py:225` 依 verdict 分組、`scripts/dd_prior.py` 讀 verdict 做基率） | **排除**，不計入任何一組，且另列排除筆數 | 校準唯一的用途是量我們判斷準不準；把沒下的判斷算成觀望會污染觀望組命中率。排除數要露出，避免靜默縮母體 |
| **PM／monitor**（PM 讀 `#decision` 當 direction 權威；monitor 掃證偽指標與催化劑） | PM：direction 視為**缺**，不得以 undecidable 當加碼或清倉依據；monitor：照常掃該檔，並把 `rearm_trigger` 當成一條到期項目追蹤 | PM 的方向權威來自裁決，沒裁決就沒方向；監測不需要方向，缺證據本身就是該追的事 |

**待持有人拍板**：要不要真加第四個 verdict enum。**預設＝不加**——為每年少數幾份動五個消費端不划算，旗標可證偽也可事後升級；新 enum 同樣免不了上表這五格對帳，只是換個地方做。

## 六、schema 瘦身：184 → 約 110–120

**結論：刪的是「固定表格的子欄」與「同一結論的第二份抄本」，不刪下游契約與判斷輸入。**

**必須留（約 100–110 條）**三類：①決策鏈（`decision_inputs` 22＋`decision_out` 7＋`premortem`／`max_dd` 5＋`archetype.primary`，約 35）；②下游直讀（`triggers[]`、`thesis` 三組供 monitor、`valuation` 六欄供估值燈與 screener，約 40）；③判斷權威欄（`moat` 四欄、`runway_post_y5`、`capalloc_grade`、`meta`，約 25）。

**可整批降 optional 或刪（約 65–75 條）**：

- **(a) 固定表格的逐欄子項（25–30 條）**——`moat.competitors[]` 8 欄、`quality` 五張表、`industry` 兩欄。改法同 WP-D B 類：key 保留、可填未展開標記（`expanded:false`＋非空 `reason`），只在該區塊承重時必展開。
- **(b) `appendix_a` 與 dd-meta 重複的投影欄（8–10 條）**——`signal`／`val`／`ma`／`verdict`／兩個 upside 改由 `gen_dd_tables.py` 從權威欄機械投影，不由 Fable 再填一次；A3「同一結論不寫五處」的 schema 版，直接砍掉一段 output。
- **(c) `reasoning` 十模組全必填 → 承重模組必填（3–5 條）**。承重**兩類都算**：①有數字流進 `decision_inputs`／`scenario`／dd-meta 的量化模組（機械判定）；②**承重的定性模組——治理可信度、護城河機制、替代威脅**——可以寫短，但必須有從證據到結論的理由，**不因為「沒有數字流下游」就降 optional**。

數量是估計，實作時逐條對帳。前提（WP-E 已完成）：Codex 複審第 2、3 點（空標記可過、新反證來源可全空）先修好，否則降 optional 只是放大漏洞。

## 七、遷移與驗證

**結論：不另建平行系統；驗證分兩層，別把兩件事混成一次測試。**

v18 基準版是 v17 同一條管線的**寫作量調整**——入口仍 `ddreport.py run`，stage 名稱不變，**基準版不新增 stage，故不需要 `--no-probe` 退路**；草判機制若日後上線才需要旗標，且預設關。**舊 `judgment.json` 相容**：新欄位全 optional，被降 optional 的欄位在舊檔仍存在，validator **只放寬不收緊**，19 份存查與 14 個 run 應維持現有 PASS／FAIL 不變（沿用 WP-D 驗收慣例：`dd_brief` 14 份重渲染逐 byte 相同）。舊檔不重跑、不回頭改。

**第一層｜內容精簡（本輪要做的就是這層）**——同一份完整證據包的成對比較：①取 2 檔（一乾淨、一爭議），`DD_REPLAY_FROM` 固定證據與模型設定；②新舊各跑一次，比六項——**核心假設有沒有變／數字對不對／反證有沒有消失／裁決是否同向／總耗時／總成本**；③人工盲讀新版 `blind_spots[]` 對該 run 的負向 finding 清單，看有無重要反證消失；④另設一例已知實質變動，驗「應改有改」。

**第二層｜研究路由（只有真的改採集流程時才做）**——用**同一截止日的原始來源集合**，審查者另外暗備幾條關鍵正反事實、不預先塞給新版，驗新流程**有沒有把它們收進來**。第一層驗不到這件事：同一份證據包裡的東西本來就都在，而輕掃最大的風險是**關鍵事實根本沒有被收到**。這一層只在 Stage 0 輪數／批次密度真的要改時才需要。

**判讀紀律**：**Stage 1G 🔴 減少不等於品質提高**——也可能只是輸入裡的問題變少了。品質先過關，再用持有人在意的**耗時與總成本**判斷有沒有效；output token 是診斷指標，不宜單憑它沒降就否決一個實際更快更省的方案。**一次成對比較只提供訊號，不能證明普遍不降品質。**

**kill condition（登記 `knowledge/rule_ledger.md` 的措辭）**：

> **v18 內容精簡**（2026-09-1x）。生日理由：v17 判斷段佔成本 63%、Fable 每檔 output 5–18 萬 token 而 `judgment.json` 僅 37KB，**疑似**大量花在重複作文與整包重寫（未證實——output 與 JSON 的差額也含思考與重試）。任一觸發即撤回：(a) 連續 5 份中 Stage 1G 出現「證據包已有而判斷未接」或「覆蓋面缺軸」類判斷級 🔴 ≥2 例 → 撤回精簡、恢復原交付標準；(b) 同尺盲審發現因精簡而漏掉的承重反證 ≥1 例 → 該類模組改強制展開；(c) 成對比較顯示**總耗時與總成本都未改善** → 精簡無效，回 v17（output token 只作診斷指標，不單獨當否決線）。加一提刪一候選：QC-51 同形狀 peer 對帳。
