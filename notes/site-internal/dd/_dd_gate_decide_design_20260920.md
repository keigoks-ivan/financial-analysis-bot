# DD 閘改成「程式清單＋典型化判斷」設計稿

日期：2026-09-20
狀態：草稿，待持有人看過再動手
範圍：只改 `scripts/dd2` 的閘（gated 段）。判斷者、採證、散文不動。

## 0｜結論

閘從「叫 opus 讀一遍找矛盾」改成「程式列題、模型只答選項、程式依信心分流」。
每一題的答案空間事先定好（是非、選一、分級），模型不寫散文。
高信心的答案程式直接處置，中信心的才交給現在的 opus 閘，低信心的列成清單交持有人。
MU 卡住的兩個紅燈，在這個設計下是兩道機械題，第一輪就會被程式擋下，run 不會停。

## 1｜為什麼要改

現在的閘是一次生成：opus 讀完判斷物與事實表，寫八條①–⑧ 的燈號與理由。
它做得不錯，MU 兩個紅燈都抓對了。問題有三個。

- 紅燈即停。run 停在閘，等持有人來看，散文與 finish 都做不了。
- 找矛盾靠模型自己掃。同一份判斷物，兩輪閘抓到的紅燈不一樣（MU 第一輪 3 紅、第二輪 2 紅，性質不同）。
- 補丁輪只能改字。紅燈若涉及機率或情境數字，補丁解不掉，MU 就是這樣。

## 2｜介面：`decide()`

一個函式，三種題型，後端可換。

```
decide(kind, context, question, options) -> {"answer": ...｜"confidence": 0.0–1.0｜"note": "≤ 40 字"}
kind ∈ {"noul": 是／否｜"choice": 從 options 選一｜"score": options 是有序等級}
```

後端第一版用 `claude -p`（本機沒有 API key，也沒裝 SDK，管線本來就走 CLI）。

- `--json-schema` 把 answer 鎖在 options 內，模型沒辦法多寫一段或拼錯選項。
- `--effort low`，模型 opus。題目是局部判斷，不需要深想。
- 提示的前綴固定：判斷物、事實表、情境檔放前面，題目放最後。CLI 有前綴快取，第二包以後只付快取讀取。
- 一包最多 20 題，回一個陣列。CLI 每次啟動有固定開銷，一題一通太浪費。

信心值是模型自報的，不是校準過的機率。這一點要記在心裡。
第二版若要接近真機率，同一包再問兩次，取三次一致率。介面不變。
若日後有 Jev 這類決策模型的 API，換後端即可，題庫與分流規則都不用動。

## 3｜信心分流

| 信心 | 處置 |
|---|---|
| ≥ 0.95 | 程式直接處置：標記、覆寫、擋下，寫進 manifest `mechanical_overrides` |
| 0.70–0.95 | 只把這幾題連同判斷物交給現在的 opus 閘，維持原輸出格式 |
| < 0.70 | 寫進 `owner_queue.md`，run 繼續往下，finish 看到未清的 queue 拒絕發布 |

門檻先照這個訂。跑完三檔（MU、TSM、TXN）看分布再調。

## 4｜第一批題庫

題目由程式從判斷物與事實表展開，不是寫死的清單。每一類寫清楚：程式先做什麼、模型答什麼、答了之後程式做什麼。

**A. 門檻是否已被自引證據觸發**（對應 gate_card ②、⑥，MU 紅燈①）
程式：對 `thesis.R[]` 每一條有 `threshold` 的，取它 `evidence_refs` 指到的 finding 原文。
模型（noul）：「照這些證據，門檻寫的條件現在已經成立了嗎？」
程式：答是且高信心，把該 R 標 `triggered=true`，`p_bull` 依 R 自訂的降幅改，重跑 `dd_decision.py` 與情境算術。判斷者不能繞。

**B. 進場路徑是否符合自身約束**（對應 ③ 口徑第 3 種，MU 紅燈④）
程式：把 `exec_line` 與 `rearm_trigger` 依句號、分號、「或」拆成路徑，取判斷者自己寫的約束句。
模型（noul）：「這條路徑在約束全部解除後才進場嗎？」
程式：答否且高信心，該路徑標 `violates_constraint`，閘輸出一條 🔴，路徑文字交補丁輪。

**C. 負向 finding 有沒有被接住**（對應 ①②③）
程式：找事實表裡負向、而 id 沒出現在 `threats`／`contradictions`／`R`／`triggers`／`evidence_dismissed` 任何 refs 的 finding。這一步純比對，不用模型。
模型（noul）：「判斷物的內容有沒有實質處理這條？」只問比對沒找到的那些。
程式：答否且高信心，🔴。

**D. 缺軸理由站不站得住**（對應 ⑤）
程式：列 `status` 為 none 或 not_applicable 的軸。
模型（score）：理由等級 {站得住｜勉強｜站不住}。
程式：站不住且高信心，🔴。

**E. 算式是真算還是估**（對應 ⑥）
程式：取 `reinvest_rate`、`roiic`、`endo_ceiling` 的 `formula_note`。
模型（noul）：「這段有可以複算的算式與輸入嗎？」
程式：答否，🔴。可複算的部分本來就由 `verify_dd_math.py` 算，不重複。

**F. 數字新鮮度**（對應 ⑦）
程式：從判斷物文字欄抽數字，對事實表 `latest_quarter_kpis` 比對期間。能比對的不用模型。
模型（choice）：比不出來的數字，「這個數字來自哪個期間？」options 是事實表的期間清單加「不在事實表」。
程式：期間比最新 kpi 舊，🔴。「不在事實表」，🟡 並記來源缺失。

**G. 漂移歸因主因類別**（對應 ⑧，MU 🟡⑧）
程式：對 `drift_watch` 每一個有變動的欄，取對應的 contradictions 條目。
模型（choice）：主因 {新證據｜情境方法變更｜價格算術｜程式預設｜無法判定}。
程式：同一欄出現兩種主因，🔴。裁決或核心假設變動被歸到「價格算術」，🔴。

**H. 裁決與一句話方向一致**（對應口徑第 3 種，MU medium 版的錯）
程式：取 `oneliner` 與 `decision_out.dca_verdict`。
模型（choice）：oneliner 的方向 {進場｜觀望｜迴避｜看不出}。
程式：與裁決不同且高信心，🔴。

**I. 壓力測試互斥**
程式：取 `stress_tests[]` 兩兩配對，只配同一情境的。
模型（noul）：「這兩條結論互斥嗎？」
程式：答是，🟡，附兩條路徑。

八類先做 A、B、C、H 四類。它們直接對應 MU 兩紅與 A/B 實驗抓到的錯，程式端也最容易展開。其餘四類第二週補。

## 5｜流程

1. 判斷通結束，`judgment.json` 落檔。
2. 程式展開題庫，分包，呼叫 `decide()`。
3. 依 §3 分流。高信心的處置先做，做完若改了 `decision_inputs` 或 `scenario_inputs`，重跑一次情境算術與矩陣。
4. 中信心的題目連同判斷物交 opus 閘，輸出格式與現在相同，`gate_audit.md` 照舊寫。
5. 低信心的寫 `owner_queue.md`。run 繼續做散文與預覽。
6. finish 檢查：`gate_audit.md` 無 🔴 且 `owner_queue.md` 為空或每條有持有人裁示，才能發布。
