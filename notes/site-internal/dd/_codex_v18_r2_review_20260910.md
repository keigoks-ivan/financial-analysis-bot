# v18 r2 二讀：主設計可進入最小實作驗證，不必再重設

2026-09-10。Codex 讀完 r2 全文，對照前次冷讀，並唯讀查核部分下游程式。未改正式檔，未跑模型／DD，未重驗 WP-E。給 Claude 指揮者的第二意見，不是生產發布放行。

## 結論

支持 r2 的基準方向：現有獨立採集 → 一次精簡判斷 → 原有跨模型閘。保留六問、單一反證來源與數字／證據保障；不再固定兩輪、不用機械單欄敏感度排除研究範圍、不強湊疑點，也不在同一輪改採集深度。現在不需要再加研究方法或重設架構。先把實作邊界寫清楚，讓第一個測試確實只量「少寫重複內容」的效果。

## 需要修正的落地描述

### 1．P1：旗標方案需要多處接線，不能寫成只改 dd-screener

設計 §五稱「五個消費端裡唯一要動程式的一處」，但同表要求 engine 新增未完成標記且不判 role_mismatch、校準排除並統計筆數、PM 不採用 direction，均不是加一個 JSON 欄位就會自動發生。唯讀確認：`scripts/engine/build_arena.py:328` 仍以 verdict 是否存在與報告齡判定 fresh，無 undecidable 分支；`scripts/build_track_record.py:225` 直接把讀入資料加入分組觀察值，無排除；`scripts/dd_prior.py:329` 起選最近報告、`:344` 原樣帶出 verdict——它是前份判斷載入器，不只是「讀 verdict 做基率」。

應撤掉「只改一處」的承諾，逐項標明由程式、模板或協議何者負責；仍傾向旗標而非新 enum。另需明訂：未完成報告的暫記觀望不應被下輪當成已定案裁決進入承繼／翻面歸因／無變動沿用；須區分「最近報告」和「最近已定案裁決」。驗收至少涵蓋：旗標穿過資料載入仍存在、未完成報告不污染校準、不被當成定案沿用、旗標解除後恢復正常。這是新旗標上線的前提，不是要求本輪一定把旗標與全部消費端一起做完。

### 2．P2：基準版與新補查分支要拆清楚

§三先說本輪唯一改寫作量，接著又規定新增一次定向補查、證據合併與局部更新；§七則說基準版只是寫作量調整。例外分支即使不是每檔都跑，仍是流程新功能。建議把第一個實作範圍定死：只做 prompt／schema／必要的渲染與驗證相容調整，不新增自動補查。碰到重要缺口先交給指揮者處理，不發布成已完成判斷。補查與未完成旗標列為下一個獨立小工作包。若本輪就做補查，應承認範圍擴大，且與純內容精簡分別量測。

### 3．P2：「只更新受影響欄位」不能變成禁止重判的硬限制

新證據可能同時改變情境、定性論據、反證處置、觸發條件與白話結論。若套狹窄的欄位白名單，會再出現修一處、其他地方保留舊結論的問題。補一句執行原則：局部更新是預設，完整保留新證據的連動影響；合併後對整份產物重跑現有驗證與 gate。影響核心論點且無法界定局部範圍時，由指揮者決定擴大重判或停在未完成狀態，不為了守住「不整包重寫」而保留錯誤。

## 小校正

- §四把 dca_role 與 EV／IRR 一起寫成情境樹投影不準確：`gen_dd_tables.py:148` 的 dca_role 來源是 decision_out.role；角色由決策矩陣決定，EV／IRR 才從情境計算而來。
- §七「裁決是否同向」可以比較，但不是品質合格的必要條件；新舊分歧時要判哪一份證據與推理成立，不能把舊答案當永遠正確。
- schema 184 → 110–120 只是估計，不是配額。舊檔 byte-identical 驗歷史相容性，另要驗新精簡形狀的六問、反證、數字與推導真的出現在交付頁面。

## 建議下一步

不再做第三輪大架構設計。先做「一次判斷、只精簡內容」的最小實作，過本地契約測試，再用相同證據包做乾淨／爭議各一組不發布比較。先看關鍵判斷與反證是否完整，再看耗時與總成本。評價由 r1 的「不建議照甲案實作」改為「支持 r2 基準版進入最小實作與驗證」。
