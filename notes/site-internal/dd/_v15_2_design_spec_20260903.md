### 2.1 `scripts/dd_sections.py`

**canonical section ids（v15.2 起強制）**：`s1`…`s14`（§13 用 `decision`）、`s85`（§8.5，條件性）、`appA`／`appB`（`<details id="appA">`／`<details id="appB">`）、`revlog`（版本修訂紀錄＋假設驗證對照）、`sources`（資料來源與缺口，選填）。`dashboard` 區＝自 `<div class="topbar">` 起到 `<nav class="dd-toc">` 之前。`dd-meta`＝`<script id="dd-meta" type="application/json">…</script>`。

對缺 id 的舊檔（v15.0/15.1 部分檔如 SE 只有 `decision`；legacy v12–v14）：`bytes`／`text`／`extract` 以 `<h2>` 文字中的 `§N` 推斷 id（`§8.5`→`s85`，`§13`→`decision`，`附錄 A`→`appA`）；`replace` 只支援帶 canonical id 的檔，找不到唯一命中＝exit 2 並說明。

子命令：

| 子命令 | 行為 |
|---|---|
| `bytes FILE [--json] [--strict]` | 每段 UTF-8 bytes、預算、狀態。預算表（KB）：`dashboard` 7（不含 head／nav／primer／style）；s1 4；s2 7；s3 8；s4 5；s5 15；s6 11；s7 5；s8 3；s85 無上限；s9 3.5；s10 5；s11 3；s12 2.5；decision 5（下限 4）；s14 2；appA 1.5；appB 3；revlog／sources 無上限。彙總列：Part I（s1–s10＋s85）佔 section 總 bytes ≥60%；商業本質（s3–s7）≥45%；估值（s10＋appA）≤6.5KB；決策層（s11＋s12＋decision＋s14）≤12KB；可見表格數（`<table` 不在 `<details>` 內）≤14；總檔 bytes 與 75–105／115 帶。超標印 `WARN`；`--strict` 時任一超標 exit 1，否則 exit 0。 |
| `text FILE [IDS]` | 可讀純文字（供 critic／patch 讀）。去 head／style／script／nav（`imq-nav-root`）／primer（`PLAIN_PRIMER_START..END`）／livebar；表格攤成 ` \| `；`<details>` 內容保留但每段前綴 `[折疊]`；頂端附 dd-meta JSON 原文。IDS 逗號分隔可只輸出部分。 |
| `extract FILE IDS` | 原始 HTML 片段，含外層 wrapper（`<section id=…>…</section>`／`<details id=…>…</details>`）；`dashboard`／`dd-meta` 亦可。多個 id 依原檔順序輸出，段間以 `<!-- DD_SECTION_BREAK -->` 分隔。 |
| `replace FILE ID NEWFILE` | 以 NEWFILE 內容整段替換該 id 區塊；NEWFILE 必須含相同外層 wrapper（`dd-meta` 則為完整 `<script id="dd-meta"…>…</script>`；`dashboard` 為 topbar 到 toc 前的整塊）。命中必須恰 1 否則 exit 2 不寫檔；成功時就地覆寫並印「ID 舊 bytes → 新 bytes」。 |
| `leaks FILE` | 可見正文機器語言掃描（去 style／script／nav／primer／`<details>`／dd-meta／`<code>`），印 `行號: 命中詞 ｜ 上下文 40 字`，末行印總數。exit 0。 |

`leaks` 詞表（regex，全部大小寫敏感）：`row ?\d`、`Hard Veto`、`Soft Veto`、`signal ?[ABCX]\b`、`估值燈`、`val ?[🟢🟡🟠🔴]`、`MA ?[✅❌🟢🟡🟠]`、`Pure MA`、`盲點 ?\d`、`PREREG`、`dd-meta`、`runway_post_y5`、`capalloc`、`QC-\d`、`archetype`、`metadata`、`硬接線`、`接線[:：]`、`Guardrail`、`校驗紀錄`、`判定規則`、`\bgate\b`、`\bF2\b`、`row 8[ab]`、`爆發候選路徑`、`循環衛星進場路徑`。此詞表同時是 QC-40 機械 sweep 的唯一權威清單（SKILL.md 不再自維一份 grep pattern）。

`qc.py` 以 `import dd_sections` 取用 `bytes` 與 `leaks` 的函式（提供 `section_bytes(html) -> list[dict]`、`leak_hits(html) -> list[(line, word, ctx)]`）。

### 2.2 `scripts/render_dd.py`

用法：`python3 scripts/render_dd.py BODY -o docs/dd/DD_{T}_{D}.html [--no-postprocess]`；`python3 scripts/render_dd.py --check docs/dd/DD_X.html`（回歸測試：把既有檔拆成 BODY 再 render，比對 `dd_sections.text` 輸出是否一致，印 diff 摘要）。

**BODY 檔**（writer 唯一產出；路徑 `.dd_build/DD_{T}_{D}.body.html`，`.dd_build/` 由 WP1 加進 `.gitignore`）內容順序：

1. `<script id="dd-meta" type="application/json">{…}</script>`
2. `<!-- TITLE: DD Viking Holdings（VIK）— 2026-08-31（統一裁決：觀望） -->`
3. `<!-- SOURCES: yfinance批量＋Excel buy-side EPS snapshot 2026-08-28＋4篇法說逐字稿全讀＋約16輪封閉式查證 -->`（頁尾來源句）
4. dashboard 區：`<div class="topbar">…</div>`、`<div class="wrap">`、`<h1>`、`<p class="note">`頂部標註、`<div class="status-bar">…</div>`、`<p class="thesis">`、`<div class="hypothesis-box">…</div>`、讀法 `<p class="note">`（模板見 html-output.md §3.3 改版）
5. `<section id="s1">`…`<section id="s14">`（含條件性 `s85`；§13 為 `<section id="decision">`）
6. `<details id="appA">`／`<details id="appB">`（B 僅循環 archetype）
7. `<section id="revlog">`、`<section id="sources">`（選填）

render_dd 組裝：`<!DOCTYPE html><html lang="zh-Hant"><head>`（charset、robots noindex,nofollow、viewport、`dd-schema-version` 取 dd-meta.schema、`<title>` 取 TITLE 註解、dd-meta 原塊、`<style>` 內嵌 `scripts/dd_template/dd.css`）→ `<body>` → dashboard → 自動生成 `<nav class="dd-toc">`（依實際存在的 section／details id 產生 pill 連結，文字對照：s1 結論／s2 論點／s3 產業／s4 商模門檻／s5 護城河／s6 成長／s7 財務／s8 財報／s85 文獻／s9 治理／s10 估值／s11 矛盾／s12 pre-mortem／decision 決策／s14 複審／appA 擇時／appB 循環讀數）→ sections → appendix → revlog／sources → 頁尾 `<p class="small">本報告由 stock-analyst {schema} 生成。資料來源：{SOURCES}</p>` → `<button class="printbtn">` → toc `<script>`（details 自動展開）→ `</div></body></html>`。

post-process（預設執行，`--no-postprocess` 跳過）：依序呼叫 `site_nav.process(out_path)`（重插 nav 單元）、`inject_report_primer` 對單檔注入導讀塊（若該腳本只有全家族掃描介面，WP1 加一個單檔函式，行為冪等）、`inject_dd_livebar`（同上，若有單檔介面則呼叫，否則略過並在 README 註明由 `update_dd_index.py` 補）。BODY 若已含 `<head`／`<style`／`imq-nav`／`dd-toc` → exit 2 拒絕。

## 4. 流程規格（WP2 寫進 SKILL.md 執行協議＋Token 紀律；WP3 寫進 critic-gates.md／html-output.md／delta-refresh.md／ddreport）

### 4.1 Writer（sonnet）契約

輸入：ticker、日期、逐字稿清單、前份 DD 路徑、輸出檔名。步驟：採集 fan-out（不變）→ 判斷性搜尋（QC-39／QC-12／Munger／QC-19，不變）→ q.py 先讀（不變）→ 條件載入 references（不變）→ 在 context 內完成全部章節 → **一次 Write** `.dd_build/DD_{T}_{D}.body.html`（單一 Write 裝不下時最多 2 次：`.body.part1.html`／`.part2.html` 再 `cat` 合併；**禁 Edit 工具**）→ `python3 scripts/render_dd.py .dd_build/….body.html -o docs/dd/DD_{T}_{D}.html` → 驗證四支：`verify_dd_math.py FILE`、`validate_dd_meta.py --report`、`qc.py FILE`、`dd_sections.py bytes FILE` → 任一 FAIL 或 bytes WARN：`dd_sections.py extract` 取該段 → 在 context 內重寫該段到 `.dd_build/{id}.html` → `dd_sections.py replace` → 重跑驗證；**禁 Read 整份輸出 HTML、禁 Read 自己的 body 檔、禁 Edit**；驗證輪次 ≤3。→ 最終回報（≤400 字＋INDEX 行＋`bytes` 表原文）。**writer 不接 critic、不做修補、不 spawn critic、不跑 update_dd_index、不 commit。**

### 4.2 Critic（opus）契約

輸入：`python3 scripts/dd_sections.py text FILE` 全文（不是 HTML、不是摘錄；約 60–80KB）；前份 DD 亦用 `text`。七軸 checklist、查證預算、合併載具、fail-safe 全部不變。輸出檔（`notes/site-internal/dd/_critic_{T}_{D}.md`）開頭固定機器可讀區塊：

```
## FINDINGS
| # | 嚴重度 | 段落 id | 一句話 | 最小修法 |
|---|---|---|---|---|
| F1 | 🔴 | s10 | … | … |
## GATE: PASS / PASS-with-fixes / FAIL
```

段落 id 用 canonical id；連動段（dd-meta／dashboard）也列。其後才是逐軸敘述。

### 4.3 Patch agent（sonnet，乾淨 context）契約

輸入：critic md 路徑、DD 路徑、要處理的 finding 編號（orchestrator 指定，預設全部 🔴＋🟡）。步驟：`sed -n` 只取 critic 的 FINDINGS 區塊 → 對每個受影響 id 用 `extract` 取 HTML → 在 context 內改寫 → 寫暫存檔 → `replace` → 連動欄位（`dd-meta`／`dashboard`）同法 → 跑四支驗證＋`leaks` → 回報「每條 finding 的處置（已修／不採納＋理由）＋改動段落 bytes 前後」。禁 Read 整份 HTML；禁 Edit 工具；**同一回合內若要重建情境樹，Bull／Base／Bear 三列必須同一框架同時重算並連動 §10.6 與 dd-meta 六個情境欄**（防半邊重建）。re-gate 後第二輪修補沿用同一 patch agent（SendMessage）。

### 4.4 Orchestrator／ddreport 鏈

writer（回報後結束）→ critic（QC-41／48／50／row 8b 任一觸發；合併載具規則不變）→ patch agent → 需要時 critic re-gate（同一 critic agent SendMessage，讀 `text` 全文）→ patch agent 第二輪 → INDEX.md 登錄（writer 回報的 ready-to-paste 行）→ `update_dd_index.py` → qc.py → commit。模型：writer／patch＝sonnet；critic＝opus（鐵律不變）。
