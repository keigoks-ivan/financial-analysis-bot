# DD 流程再設計：研究寫一次，獨立審一次，程式負責組頁

日期：2026-09-11。狀態：設計稿，尚未實作、未呼叫模型、未切換正式流程。

目標是降低完成一份合格報告所需的總時間與總用量。品質優先於速度；節省不得來自刪除原始證據、略過反證、放寬數字檢查或縮成內容不足的報告。

本次重設的是「證據收集完成之後」的研究、審核、呈現流程。資料收集先保留，避免同時改來源與判斷而無法歸因。原始 evidence 全文、最新逐字稿、前三季摘要、前份判斷、既有 facts 索引都保留。快速版、回放測試與現有投資判斷門檻保持原樣。模型供應商不作為本設計前提；實作由 Codex 處理。

已確認的問題是重複輸入、長輸出、修補缺少欄位規格、審核讀到舊契約。大量思考 token 本身不代表浪費；本設計不先降低思考能力或換便宜模型，先驗證交接與輸出重複能省多少。

## 正常流程只保留兩次研究模型呼叫

```mermaid
flowchart LR
    A[凍結完整證據與來源索引] --> B[研究者：結論、依據、假設與行動條件]
    B --> C[程式：結構驗證、計算與組頁]
    C --> D[獨立審核者：核對來源、反證與判斷]
    D --> E[程式：驗收實際產物]
```

| 負責者 | 交付什麼 | 取代什麼 |
|---|---|---|
| 程式 | 凍結輸入、組包、計算、存檔、渲染及記帳 | 模型執行寫檔、語法檢查與狀態回報的工具往返 |
| 研究者 | 一份結構化研究內容，文字直接面向讀者 | 同一結論分別寫在 reasoning、plain、散文檔的多次改寫 |
| 獨立審核者 | 有依據的問題清單，或通過結論 | 要求作者解釋機械欄位、重算已經驗過的全部公式 |

「兩次」只指證據完成後的正常路徑，不包含既有資料收集模型。審核者保持獨立、不同於研究者的模型；同一次試驗不再同時更換模型，避免把模型差異誤判為流程改善。

研究者直接回傳完整結構化結果，由程式寫檔並檢查。取消研究者的 Bash 自檢及單獨 DONE 回覆。執行器是否支援受 schema 約束的直接輸出、能否容納完整結果，必須先用離線契約測試確認，不能假定現有 CLI 已具備某個旗標。輸出截斷即失敗，不以省略欄位或反覆整檔續寫掩飾。若現有傳輸方式無法可靠承載，就先保留一次 Write，取消不必要的自檢往返，單獨記錄這項限制；不得默默改用另一個付費供應商。

## 研究內容只存一份，細節仍保留

沿用現有 v19 的六問、假設、情境、反證與行動條件，不增加另一套研究 schema。六問的 `verdict` 與 `reasoning` 寫成可直接閱讀的中文；結構欄位保留機器需要的數值、分類與引用。程式沿用 `dd_project` 提供既有下游所需的視圖，逐步停止要求模型另外填重複敘述。

完整頁面的章節逐項指定來源，不能因取消散文模型而留下空章：

| 讀者內容 | 現有內容來源 |
|---|---|
| 摘要與裁決 | oneliner、六問結論、決策結果 |
| 投資假設與失效條件 | thesis.H、thesis.R、single_thing |
| 生意、護城河、成長、資本配置、估值 | 對應六問的結論與理由，附既有證據表格 |
| 可能看錯的地方 | counter_evidence 的三視角、不採納理由、矛盾裁定 |
| 情境數字、同業、財務歷史、法說原話 | 既有計算結果與來源資料；缺資料不得用佔位表交差 |
| 新資金、已持有、清倉、監測與前次變動 | action_conditions、triggers、kill_metrics、contradictions |

以上為內容歸屬，實作時須逐一對照現有 section id。不存在可供重用的必要內容，回到同一份研究欄位補寫，不增加獨立散文檔讓模型重述整篇。理由包含傳導過程、限制及反方證據，不以一句 verdict 代替分析。先以現有版面組成完整頁並做逐章對照，通過後才停用獨立散文階段；快速版始終保留。

不設新的全文最低字數，也不為省錢強迫每題只能一句。長度與輸出 token 是觀測值；章節完整、推理能理解、數字與來源對得上才是驗收條件。

## 來源一次固定，判斷與審核看同一份材料

建立機械來源索引，不增設來源整理模型。已有 facts 保持為方便取用的索引；原始資料不被索引取代。原文以本次 run 的快照保存並計算雜湊，避免雲端檔案後續變動讓引用無法重現。

研究者與審核者都取得完整 evidence、最新逐字稿與全部既有摘要。只做省空白與移除完全相同的重複副本，不按正負方向、重要性或是否已引用篩掉資料。摘要裡的原有定位與原句仍保留。前份判斷標明是歷次判斷背景，不能當本期外部事實。

沿用現有 `source`／`evidence_refs` 等引用位置，統一語法而非再開一張數字事實表。例如來源索引可提供 evidence 的完整欄位路徑，以及逐字稿的檔案識別碼與段落範圍。顯示的引用名稱由程式轉成可點閱的來源名稱。實作前先確認各引用位置的 schema，不把任意格式塞進受限的 `fact_refs`。

來源驗收區分三類：

- 已公布事實：數值、單位、期間及來源定位必須能核對。只有「逐字稿」三字不算完整引用。
- 衍生計算：列來源輸入與公式，結果由程式算；不能要求它有一條同值的外部 fact。
- 情境假設：明標假設，附推論依據；不能偽裝成已公布數字。

機械檢查確認檔案與定位存在、原文可取；語意、口徑與數字解讀由獨立審核負責。歷史事實缺可核對來源會留下警示；若是支撐估值、風險或行動條件的關鍵數字，不能只剩警示就視為合格。機械層不能判斷何者承重時，交審核者明確判定，不靠全頁數字正則猜測。

## 輸出契約要完整，修補資料要精確

schema 是欄位型別、合法分類及 required 的唯一來源。首次研究包帶完整判斷者欄位規格。修補包直接附被點名欄位的 schema 片段、目前值及錯誤，不只給「missing required key」。這能處理本次先缺 impact、補成長句後才被擋的問題。

修補只接受 v19 的正式路徑，不允許用舊版頂層 `evidence_dismissed` 混入。兩個位置同時出現就報衝突，不按陣列順序合併、不丟掉多出的內容。修補先套在記憶體或暫存檔，完整驗證後才取代候選檔；失敗保留前後版本與原因。

格式處理只准做經證明不改內容的轉換。長文字搬到 watch 並把 impact 留空，可以保留文字，但須明列未評級；不能宣稱已補完等級。未知分類與缺少研究判斷不能用 null 自動消掉錯誤。

機械數字的權威固定如下，審核者不再要求作者補說明：

| 項目 | 權威來源 | 作者是否填結果 |
|---|---|---|
| 三情境 EPS、終端倍數、機率 | scenario_inputs | 作者提出假設 |
| IRR、EV、asym | dd_scenario 產生的 scenario_meta，經既有解析器供下游讀取 | 不填 |
| moat.combined、score | 既有投影規則 | 缺省時由程式補；審核讀投影結果 |
| 裁決與決策矩陣 | dd_decision 的既有規則 | 不手改機械輸出 |
| 倉位與行動條件 | 現有判斷者欄位與來源依據 | 作者負責；不能被投影吞掉 |

審核包同時標明原始研究欄位與程式計算的結果，不建立另一份可手填的結果副本。`decision_inputs` 的機械欄位缺省或留空，不要求在 evidence_dismissed 偽裝成證據不採納聲明。ROIIC 缺輸入、算式或口徑仍是實質問題，不能連同欄位誤報一起取消。

## 修補最多一次，內容改過仍要審

本稿把「修補限一次」明確定義為每份報告最多一次模型修補，格式與研究修補共用額度。這比目前判斷段與審核段各有一次更收斂。程式自行重算、重新組頁不算模型修補。

| 發生什麼事 | 怎麼走 | 最多模型呼叫數，資料收集之後 |
|---|---|---:|
| 首次研究合格，審核通過 | 研究 → 審核 → 組頁驗收 | 2 |
| 首次研究格式錯，修補成功 | 研究 → 唯一修補 → 審核；再有實質問題就停 | 3 |
| 首次研究合格，審核發現實質問題 | 研究 → 審核 → 唯一修補 → 再審 | 4 |
| 修補仍錯、來源仍缺或重審仍不合格 | 留下原因與產物，停止完成流程 | 不再追加 |

再審仍保留完整來源，任務聚焦變更及連帶影響；若修改假設、機率、門檻、來源判讀或裁決，必須核對相關全文。引用編號出現只能證明已引用，不能取代內容審核。

不加「哪些修改可以省掉第二輪」的複雜分類引擎。任何模型修過的研究內容都要獨立審。沒有修改研究內容的確定性組頁或格式整理，由既有驗證器處理；不能用這個例外挪動或刪除研究意思。

## 只保留兩個驗收時點

研究交稿時，程式統一檢查 schema、來源定位、情境算術與現有判斷一致性。獨立審核聚焦證據採納是否合理、反證是否遺漏、推論與行動條件是否成立、文字是否能讓讀者理解。審核不必逐項重演已驗過的程式計算，但仍要檢查假設與計算口徑。

最終產物完成時，沿用同一套檢查確認研究、來源、計算結果、審核及實際 HTML 版本一致。包含折疊區與附錄。審核通過後來源、研究或計算結果變動，該通過結果失效；僅重排相同內容的 HTML，重跑呈現檢查即可。不可複算、資料缺口冒充完整表格、關鍵反證未處置，都不能發布。

每次呼叫以獨立編號記帳，不能因 resume 覆寫掉舊成本。凍結輸入放在穩定前綴，變動的結果、錯誤與差異放後面，以利執行器可用時重用快取；不預先承諾命中率。報表分列一般輸入、快取寫入、快取讀取、輸出、思考與美元，明列各自是否包含關係。

## 先驗品質，再驗效率

先做不呼叫模型的回放：schema 缺型別提示、修補新造非法值、錯誤 v18 路徑、兩筆 PFAS 不採納理由被吞、最新逐字稿未帶進審核、衍生欄位誤報、舊審核重用、財務空表、附錄洩漏，全部要能重現與攔截。原始證據的鍵值及逐字稿內容做完整性比對，不能只比檔案大小。

正式付費對照另需授權。先用凍結的 FIX 證據驗已知回歸，再用兩份在實作前選定、未參與設計的既有案例檢查泛化，覆蓋不同公司型態。新舊版本用相同來源、模型與設定，所有失敗呼叫與人工介入都列帳。由未參與生成的審閱者做隱藏版本標籤的逐章比較：承重數字、反證、假設、行動條件與可讀性。裁決相同不代表品質相同，總分平均也不能掩蓋關鍵漏失。三例只能作初步放行證據，不宣稱證明普遍不退步。

效率目標採工程驗收值，不是收益承諾：同口徑研究加審核，中位時間先以 20 分鐘內、用量成本 8 美元內為目標；累計輸入與輸出各爭取降低 30%。完整頁面另計從證據凍結到驗收完成的時間與成本，不能省略原散文階段而假稱全鏈已變便宜。第一次資料收集與後續資料重用分開列。

若品質達標但效率未達，記為效率候選未通過，不降低證據量或思考能力湊目標。若品質不達，即使更快、更便宜也不用。FIX 的已知來源、必要財務序列與現有語意缺口沒有補齊前，不能把新流程視為可正式取代現行流程。

## 實作順序與刪除對象

先修明確錯誤：修補提示附欄位規格、禁止錯路徑與資料丟失、補審核所需逐字稿、寫清機械欄位權威。這些不改研究門檻。

接著讓研究者的既有文字直接供頁面使用，逐章核對內容；停掉獨立 prose 呼叫後，刪除其模型重派路徑與重複提示。將模型寫檔、自檢、DONE 的往返交給程式。以離線測試證明完整輸出可承載後，才切換執行方式。

最後以每份報告一筆修補額度取代分散的重試分支，保留兩次獨立審核的必要例外，不增加新的自動語意修補器。舊方案作離線基準，避免同時維護兩套正式規則。

預計沿用的修改位置是 dd_bundle、ddreport、dd_project、既有 judge 與 gate 提示、render_dd 及其測試。引用契約若需擴充，先列出現有欄位差異再修改，不另建平行 schema。技能檔、投資門檻、快速版、資料收集與公開頁面在設計階段均不動。
