# WP-D 第二意見：方向合理，先補契約接線再量成本

日期：2026-09-10。範圍：交接檔 `_wpd_handoff_for_codex_20260910.md`、WP-D commit `a7f8b24d8` 及目前下游程式。只讀複審，沒有修改正式檔、呼叫模型、跑 DD、commit 或 push。此份是交給 Claude 主 session 的第二意見，不是發布放行。

## 結論

反證只寫一次、移除湊數配額、完整表格依問題展開，方向正確。但目前「少寫」已落地，「省略時如何保住品質」及「新格式一路通過下游」尚未完全接好。先修以下五點；不需要恢復整套長篇必做，也不需要再加一份 LLM 審查。

## 發現

### 1．P1：合法的原因分組會被另一層驗證誤擋

位置：`scripts/validate_judgment.py:610`，WP-D 新形狀在 `scripts/dd_schema/judgment.schema.json:454`。

`prior_field` 已允許陣列，但機器欄名的文字外洩豁免仍只匹配字串路徑 `contradictions[0].prior_field`，不匹配 `contradictions[0].prior_field[0]`。測試中，字串 `runway_post_y5`／`archetype` 都通過；改成合法陣列後，兩者均報 FAIL。

影響：按照新規則交稿反而失敗，可能增加修稿與模型重試；是否真的造成整包重寫仍須從實跑帳確認。

最小修正：把此機器欄位的整個子樹納入同一豁免，不放寬讀者文字的檢查。補字串與陣列等價測試，至少含上述兩個欄名。

### 2．P1：四個可不展開區塊允許沒有理由的空物件

位置：`scripts/dd_schema/judgment.schema.json:121`、`:196`、`:225`、`:240`；規則承諾見 `scripts/dd_prompts/judge.md.tmpl:45`。

schema 只把型別改成 array 或 object，沒有要求 object 的 `expanded=false` 與非空 `reason`。四個區塊各測 `{}`、`{"expanded": false}`，共八例，完整 `validate_file` 全部沒有 FAIL。

這直接違反交接檔保留必填 key 的理由：要留下省略理由以便稽核。空物件甚至可能呈現成空表，而不是可追問的未展開說明。

最小修正：驗證 object 必須是有效的未展開標記，且有非空理由。是否「真的不承重」仍是判斷問題，不要假裝靠字數或關鍵字就能驗證理由品質；審核直接讀此理由與既有情境假設即可。此處 generic validator 不支援完整 JSON Schema，不能只加它不認得的 oneOf。

### 3．P1：撤掉舊反證必填後，新的唯一來源也可以全空

位置：`scripts/dd_schema/judgment.schema.json:472`–`:500`。

用原本驗證通過的 BE 存查複本，移除 `failure_story`／`second_failure`、清空 `blind_spots`，並把 `trap_analysis` 留成只有 verdict，完整 `validate_file` 仍無 FAIL。這不是證明所有風險欄都空，也不是證明跨模型閘一定放行；但三視角的承接保障目前只有 prompt，機械契約沒有接住。

最小修正：對新格式檢查三視角均有實質紀錄，或該視角有明確不適用的理由。舊檔可以保留相容路徑，但不能「舊來源不再需要，新來源也不需要」。用明確版本或形狀識別，避免誤傷合法歷史存查。不要重新要求三篇散文。

### 4．P2：反證唯一來源仍會被可選摘要遮住

位置：`scripts/dd_brief.py:446`–`:450`；新分組顯示在 `:649` 起。

只要 `plain.how_to_lose` 非空，頁面該段就直接回傳摘要，不呼叫新的 `render_premortem`。測試放入三視角各一條独有證據，再加一句「反證詳見下列三視角」，該段實際只輸出這一句，三條紀錄皆未呈現。

此優先順序本來就存在；WP-D 把實質內容搬到唯一來源後，它成為新設計的接線缺口。交接中「14 份重渲染逐 byte 相同」只能證明舊形狀相容，不能證明新三視角一定可見。

最小修正：新格式固定呈現 canonical 反證；可選摘要只能放前言，不能取代反證。舊格式維持相容。另補整頁測試確認三視角實際出現在交付 HTML。

### 5．P2：產出端放寬，跨模型閘仍要求舊工作

位置：`scripts/dd_prompts/gate.md.tmpl:37`、`:40`；`scripts/dd_prompts/gate_contract.md:29`、`:56`、`:76`。

新規允許多個漂移欄共用一個原因條目，但 gate 仍問每欄是否有「獨立條目」及舊的歸因排序。機械 coverage 允許一條查詢，gate 則仍以少於兩條發問。後者交接有明示刻意保留，前者同樣需要處理。

這不代表模型每次都必然判紅；它表示同一份合規產物被兩份互相矛盾的要求評判，可能迫使模型補回已取消的作業。

最小修正：維持跨模型閘的權限與判斷嚴格度，只同步它驗的契約——每欄有原因映射、裁決／方法變更有實質解釋；搜尋是否切題且充分，而不是重新湊次數。需要指揮者明確批准同步 gate 文案，不自行越過「閘不准動」的範圍。

## 其他交接問題的判讀

- 「條件式展開是否太鬆」：目前最先要解的是省略理由可全空。至於模型是否會系統性逃避承重分析，靜態閱讀無法證明，要用同證據盲審驗證。不要先加十條例外。
- 「原因分組會否掩蓋方法改變」：`_prior_fields_of` 只证明欄名被列出，不驗證原因是否真實；這個限制在舊單欄版本就存在，分組會擴大其影響。應由既有 gate 比對前後假設，而非再建一套文字配額。裁決／情境方法變更不能併入純價格原因，需補正反測試。
- 「delta 升級條件是否保守」：WP-D 不足以證明 delta 安全。新事件類別只是部分觸發；同一 claim 的改值／移除、新逐字稿、用戶筆記、規則版本等失效條件需另驗。先前 review 的問題未在本輪重新逐一跑過，不宣稱此次已修復或重新驗證。
- 「資本配置十年全史」與 `capital_returns` 的邊界要確認：後者實際是逐年的回購、股利、資本支出、研發表，不天然等於十年併購全史。條件式省略不能連近期現金分配的基本面判讀一起省略。這是範圍提醒，未據此宣稱已有漏判。

## 如何回答「現在為何變慢」

不是單純 skill 檔案變長，而是它要求模型做的工作變多：同一判斷重寫多處、每個模組固定交表、過多格式約束，以及驗證衝突造成修稿。交接統計中，判斷段占成本 63%，輸出遠大於最终 JSON；這支持優先檢查思考與重試，但不能從 token 差額精確拆出兩者各占多少。

WP-D 有減少重複工作的機會，但輸入包反而增加 1.9%，所以「改了」不等於「已經更快且品質相同」。先修接線，再量淨效果。

## 最小的後續驗證

1. 先修上述程式契約與文案衝突，用本地測試驗證，不消耗模型額度。
2. 由持有人點名股票、Claude 指揮者指定不發布的測試方式。固定同一份證據及模型設定，比較舊新流程各一次全套判斷；檢查總耗時、input／output／cost、驗證失敗與重試原因，以及重要基本面／反證有無漏掉。只比歷史不同證據的 token 不足以歸因。
3. delta 另設一例已知實質變動：驗證「應改有改」，而不只是測無變動時跑得快。

一次成對測試可以判斷改動是否有效，不能證明普遍不降品質。先拿最小成本取得訊號，再決定是否擴大樣本；不用先花錢重跑大量報告。
