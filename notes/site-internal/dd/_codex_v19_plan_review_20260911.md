# v19 計劃複審：支持分工精簡，先做 H1／H2，暫不做 H3 的跳軸方案

2026-09-11。已讀 `_v19_plan_20260911.md` 全文，並對照目前覆蓋軸與判斷輸入契約。只審設計，未改正式檔、未跑模型／DD。本意見不是發布放行。

## 結論

這次比 v18 更直接針對原始目標：讓昂貴判斷模型少做資料整理、重複填值和呈現工作，而不是單純縮短文字。支持六問事實表、一次主要判斷、單一反證來源及機械呈現。五個出手點可作職責分組，但不是證明已減少思考量，也不是五個模型呼叫。

不建議三包全部照稿開工。先修下列分工邊界，做 H1／H2 的最小閉環；H3 改採集範圍另議。第一次是否減半仍是待驗目標，不能只比較 Fable 帳單，要含新增 sonnet 整理與修補成本。

## 回答三題

### 1．事實表可以做，但「摘要＋負向原文」不足以保證判斷不失真

事實表的價值是替 Fable 找資料、對齊期間與單位，不是替它決定哪些事實值得相信。

除了負向 findings，須保留會影響六問的正向反證、中性結構變化、來源衝突與缺口。FIX 已經示範：PFAS 是 direction=0，關稅緩解是 direction=+；只帶負向原文不能完整呈現問題。只带「已被引用」的 finding，也會把前一份或整理者沒有注意到的資料繼續排除。

最小做法：facts 每條有穩定 id、值與期間／單位／口徑、來源定位；另保留精簡的 findings 清單，不按正負方向裁掉項目。對承重或有衝突的項目附原文片段，完整原始包保持可追溯。來源稱「將成長」應記為管理層或分析師預期，不能被整理成已實現事實。

可以縮短輸入，但不要把 15KB／120KB 當硬品質上限。判斷需要資料時，不應因超過篇幅配額而失去它。審核模型也須看得到 Fable 實際採用的事實、原文與新增反證；不能再次出現 Fable 引最新逐字稿而 gate 無法核對。

### 2．程式可以計算與映射，不能從六句散文自行補出判斷

| 項目 | 可以交程式的部分 | 必须由判斷者明示的部分 |
|---|---|---|
| EV／IRR／AR、倍數與 PEG | 已定義輸入及口徑下的算術 | EPS 路徑、終端倍數、機率、適用估值尺與正常化口徑 |
| path_risk | 將已判定的 Max DD 範圍依既有切點轉燈號 | Max DD 範圍與理由 |
| moat 分、方向／等級 | 組合已明確給出的子評分、依固定門檻映射 | 優勢機制、持續性、子評分與重要性；不是從毛利率自動判有護城河 |
| runway 燈 | 對已判定的市場空間與階段套用規則 | 未來滲透率、新曲線是否可信、成長可持續多久 |
| capalloc_grade | 已確認適用性與輸入後，依現有計分卡加總 | 併購 NOPAT 歸屬、ROIIC 代理、不可比資料與不適用項的處理 |
| 品質分、估值燈 | 已定義的權重、門檻與算式 | 盈餘是否正常化、一次性因素、分母爭議、判斷性例外 |
| plain／reasoning | 引用、排版與固定句型呈現 | 真正的證據到結論理由；程式不能無中生有補理由 |

因此「§7／§8／§9＝0 次 Fable」應改成「0 次 Fable 抄表／摘要」，而不是不讓它看財務品質、指引與資本配置的重要問題。這些判斷可併入現有五個出手點，無須新增出手點或模型回合。

新 answers 不宜只有六段文字。每題保留必要的結構化判斷值與短理由，再由程式投影成既有 decision_inputs。純機械欄不要要求 Fable 重填；既要 Fable 填 22 欄、又要程式從六問重推相同欄位，會重新引入重複與矛盾。

### 3．五個核心軸可作優先順序，不能作排除其他風險的白名單

不同意目前三個例示觸發器：

- 單一客戶 ≥20% 才查集中度：集中度數字本身往往要查才知道；客戶數分散也不代表終端需求或共同付款能力分散。
- 只有金融／受管制才查監管：FIX 的冷媒與施工規範正是不依賴此分類的反例。
- 有海外產能才查地緣：國內生產仍可能依賴進口零件、海外客戶或受管制產品。

合理界線是「基本暴露確認」與「專項深查」，不是「沒數字就不查」。可以利用既有年報風險揭露、數字與查詢結果一次覆蓋多個面向，不要求每軸獨立作文或獨立 spawn。確認有暴露、異常、衝突才深入；未知不能當成未觸發。

H3 不必先做。H1／H2 已經能測 Fable 工作轉移是否有效，先保持採集範圍，避免同時改兩件事而分不清節省來自分工還是漏查。若日後做 H3，重放完整 evidence 只能測觸發函數，不能驗首次尚未知道那些數字時是否查得到重要事實；需要另驗採集覆蓋，不能靠第七節固定證據包的比較代替。

## 開工前只需補清楚的四個接線界線

1. **新契約不可能讓 J1／J6／gate_view 真正「一字不動」。** 它們目前依舊欄位取資料。可用一處程式轉接，把新唯一來源提供給既有檢查／渲染；保留的是檢查語義，不是原讀檔路徑。不得靠模型再寫一份舊格式。H1 fixture 要驗實際 J1 可達性、監測器收到致命指標、關鍵數字／理由有呈現，不只驗頁面有六個標題。
2. **正規化不得代填判斷。** 路徑、確定的欄名映射、單一物件包成陣列可以；缺 note 的理由、評級、false、門檻與機率不行。無法修補或重要資料不足就停止交給指揮者，不必等新 undecidable 功能，但不能用預設值發布成已完成。
3. **delta 先當受測功能，不以「已有程式」視為可直接正式沿用。** schema／規則版本相容、事實改值或刪除、來源修訂與新逐字稿都須納入失效判斷；只有結果翻面才升級不是完整保障。第二次測試要有已知實質變動，不是只看原封不動重跑多便宜。既有 judgment 沒 facts 時也要說清楚如何建立有來源的事實表，不能把舊結論當事實。
4. **驗收不能保證 33 份舊檔全 PASS。** 近期才揭露舊檔數字不一致；應要求舊格式可讀、預期 PASS／FAIL 不被誤改，不應為保持全綠放過錯誤。kill condition 的「且無法補一句規則修」應改成：發現重要漏失即判該候選未通過，修正後重驗；不能因「將來可能修」就視為已通過。

## 建議的最短前進路徑

只需把本稿上述邊界補進既有計劃，無需再寫一版長設計稿。先做 H1／H2：事實整理＋少量結構化判斷＋程式投影＋一次主要模型呼叫，沿用原採集範圍。先在已存證據上驗首次成本，再驗一次含實質變動的 delta。不上完整版散文，不順便實作 H3。

對主線的判定：**v19 的分工方向可以前進；「判斷也能純算」與「無數字就跳過風險軸」兩個假設需撤掉。** 保護的是重要研究，不是舊模板；要省的是模型不必重做的工作，不是把判斷責任藏進整理模型或程式。
