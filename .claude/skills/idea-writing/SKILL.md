# idea-writing：投資想法頁寫作規格

2026-10-13 定。起因：五篇想法頁的頭尾一致、中間各寫各的，反方意見只有一篇有，「還沒查到的」只有兩篇有。代理人那篇第一版把「Arm 拿到架構份額」當成「Arm 賺到錢」，股價走勢反過來（AMD、Intel 漲幅大於 Arm）才整頁重寫；這類錯誤靠固定的檢查步驟比靠臨場想到可靠。

原則：**固定要回答的問題，不固定章節。** 題目差異大（產業鏈、商業模式、國家政策、總經、單一公司事件），中間的分析方法跟著題目走。標題、順序、篇幅都不規定。

中文照 `zh-analyst-prose`。這份規格是寫作紀律，不是裁決閘，不登記 rule_ledger。

## 一、寫之前必走的四個視角

每篇都要走過四個視角，但頁面上只寫真正改變結論的那幾個，不要每個視角各開一節。不適用就寫一句「不適用，因為……」，或者乾脆不寫。

| 視角 | 要回答的問題 | 做法 |
|---|---|---|
| 拆解（第一性原理） | 結論最底層靠哪個數字？ | 把結論拆到成本結構、物理限制或單位經濟（單價×數量、產能×良率、殖利率＝實質利率＋通膨補償）。拆不下去就直說拆不下去，不硬套。 |
| 供需與瓶頸 | 哪裡缺、缺多久、誰是邊際買家或賣家？ | 看交期、產能擴張需要幾年、替代品、價格彈性。合約價優先於現貨價。 |
| 利潤落在誰 | 這件事發生了，錢落在誰的損益表上？ | 份額不等於獲利：分清楚收權利金的、賣整顆產品的、出租的、自用不外賣的。看議價力、抽成會不會被競爭壓低、上下游誰缺貨。這是唯一有實際錯例可以佐證的視角，每篇必走。 |
| 市場已反映什麼 | 股價或利率裡已經有多少？ | 相關標的近期漲跌、估值倍數對歷史、共識預估。前三個視角回答「會不會發生」，這一個回答「還能不能賺」。 |

## 二、頁面上必答的五題

1. **主張**：主張方框（`<div class="thesis">`）寫成一句會錯的話，附上時間範圍。一頁摘要的最後一條寫「撐住結論的是哪個視角、它發現了什麼」，用白話，不要寫成「本文採用……」。
2. **對錢的意義**：影響哪些持股、哪份 DD 的裁決、還是 Rulebook 的哪一層。可以是受惠／受壓公司表、押注分層，或「對 DD 的建議」。只講產業不講錢的頁不算完成。
3. **反方**：至少一條最強的反對理由，每條要回應它對本文的影響（削弱哪一句、不影響哪一句）。產生方式見第四節。
4. **還沒查到的**：條列結論依賴、但還沒找到一手資料的事。讀者要能分出哪些是查過才下的結論、哪些是推定。
5. **查核點＋收回條件**：「查核點」與「什麼情況收回這個想法」兩節，加上 `ideas.json` 一筆（status active）。查核點寫法沿用既有原則：不用單一有雜訊的數字，看趨勢、公司財測與說法、同代比較；公司不公布的數字不能當條件；寫完用幾則真標題測試，一則新聞配到超過 3 個查核點就收緊關鍵字。

## 三、看題型選用的模組（適合才用，不強制）

| 題型 | 常用模組 | 現有例子 |
|---|---|---|
| 產業鏈、主題 | 推論鏈、判斷條列、受惠公司表 | ai-scissors |
| 商業模式、平台競爭 | 判斷條列、三種情境、核心押注／情境押注／受壓 | consumer-agents |
| 國家政策、地緣 | 卡在哪（瓶頸拆解）、錢從哪裡來、成敗紀錄、三種情境 | china-litho |
| 總經、利率 | 拆解、已定價／未定價、三種情境附機率、監測儀表板、事件時程 | bond-repricing |
| 單一公司事件 | 講了什麼／沒再提的、舊承諾兌現、哪些目標靠假設、現價隱含什麼、管理層原話 | marvell-investor-day |

三種情境要寫機率時，註明是主觀機率。

## 四、反方怎麼產生

- 由獨立的審稿角色冷讀初稿後寫，作者不寫自己的反方。派 sonnet agent（模型與作者不同），只給頁面檔案，要它找最強的二到五條反對理由，每條附數據並寫「對本文的影響」。
- 不要用 `industry-thesis-critic`：它限定在決策當下使用，禁止在寫作當下使用。
- 段首放一行說明：「以下由獨立審稿角色冷讀本文後寫成。」反方指出的錯誤若被接受，直接改正文，說明行裡註明哪幾點已改正文。

## 五、技術注意事項

- 主張方框下面的 `<div class="cpstatus-wrap" id="cpstatus"></div>` 不能被替換或刪掉，否則 mountStatus 會報錯、查核點狀態表消失。改完後比對頁面裡每個 `getElementById` 的 id 都還在（目前是 `cps`、`cpstatus`、`hit-total`）。
- 新段落沿用頁面既有的 class（`imq-table`、`tbl-wrap`、`note`、`muted`、`summary`），不加新 CSS。
- 已經有早報命中紀錄的查核點不要重編號、不要改定義，否則 `idea_hits.json` 與 `research.json` 的歷史對不上。
- 新想法流程：先分析、使用者同意後才寫頁面並加 `ideas.json`。`company_names` 用英文小寫，路由表認不得的公司一定要列；themes 只用路由表有的。
- commit 前跑 `python3 scripts/qc.py`。

## 六、回頭補舊頁

- 只補缺的項目，不動既有分析與查核點。
- 補的段落直接寫成頁面的一部分，不寫「補充」「新增」「之前漏了」；改了什麼只寫在 commit 訊息。
- 補段用到的數據若晚於頁首的「數據截至」日期，在該段第一句註明數據日（例如「股價截至 10/13」），頁首日期不改。
