A0 作為 10 月回顧點的正式提案

決策備忘（非公開研究頁；可含建議）・生成 2026-09-06・noindex

提案內容一句話：把實單系統的曝險上限（cap，能借錢把部位放大到幾倍）從 cap 1.5 （可以借錢把部位放大到 150%）降到 cap 1.0（不借錢，兩條腿各自最多壓 100% 的錢）。 下單的判斷規則本身不變，只把每次最多能調動的部位上限（clamp）從 75 個百分點／腿降到 50 個百分點／腿；其餘（52 週均線判斷要不要持有、依波動率自動調整倉位、美台兩市場各半 50/50 兩腿）完全不動。下文 A0＝新配置，A＝現行配置。

理由（用一句話說：不求賺最多，但求輸不到最慘）：慢熊行情真的來了，A0 一樣能發揮防守作用； 慢熊沒來，A0 平常少賺一點，但也不會在急跌時因為借錢加碼而被放大虧損、也不用付借款的利息差。

下面十二段對照表用到的四把尺：年化報酬（CAGR，帳戶平均每年賺多快）、 最大回撤（MDD，從最高點到最低點最深跌掉多少）、Calmar（年化報酬 ÷ 最大回撤，數字愈大代表每承擔一分下檔風險換到愈多報酬）、 Martin（另一種算法的風險調整報酬，對「跌下去以後拖多久才回本」更敏感）。判斷「A0 是否比較好」一律看 Calmar／Martin 這類風險調整後的指標，不是單看誰的年化報酬數字比較大。

二、換成 A0 要付出什麼代價、要動哪些操作

預期 CAGR 犧牲（同段歷史窗回測差異，非未來保證）：美股 14.10% → 12.68%，約 −1.4 個百分點／年；台股 22.98% → 19.05%，約 −3.9 個百分點／年。

程式碼改動：src/vol_target_backtest/update_long_track_w52_adaptive.py 的 CAP = 1.5 → CAP = 1.0；EXEC_CLAMP = 50.0 * CAP 公式不變、 數值自動從 75pp/腿變 50pp/腿；LEV 字典兩市場 fullstack 行需換成表 1 的 A0 數字； 頁面敘述文字同步改「cap 1.5」為「cap 1.0」。

去槓桿、去借款：SPREAD（借款部位年息 1.5%）只在曝險 >100% 時計息， cap1.0 下曝險永遠 ≤100%，這筆利差自動歸零；沒有借款部位，也就沒有被追繳／強制平倉的曝險（本站 未對此定價，但質性上直接拿掉這個未量化風險）。

稅務／手續費中性：執行層規則（20pp 門檻、10% 格、7bps 成本慣例）不變， A0 調整頻率與 A 同一數量級，不構成額外稅務或手續費結構性變化。

三、如果不換，理由是什麼（誠實列出反方意見）

  1. A 在這段歷史上確實多賺：美股多 1.4pp/年、台股多 3.9pp/年，複利 10-20 年是可觀的終值差距。
  2. 台股 cap1.5 的 Calmar 優勢方向穩健：三種執行層 × 五個判定錨點 15/15 全部支持 cap1.5 較高， 但幅度極不穩定（A2 下 +0.008 至 +0.233），放棄的是一個「方向真、幅度運氣」的優勢。
  3. 槓桿是這套系統宣稱「真波動率目標」的必要成分：改成 cap1.0 後系統退化為單純「均線閘門×去槓桿」， 有人會主張這不再完整體現 Moreira-Muir 式 volatility-managed portfolio 的原始設計。
  4. 用戶已做過一次知情決策：2026-07-17 選擇 cap1.5 時已知美股槓桿是劣勢仍維持槓桿，這次提案等於 要求推翻一個已是「知情」的既有決定，門檻應比首次決策更高。

四、我們的建議，以及什麼情況該收回這個建議
